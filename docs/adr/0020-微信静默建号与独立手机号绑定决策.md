# ADR 0020：微信静默建号与独立手机号绑定

- 状态：已接受，源码和本机开发库迁移落地；平台和应用动态验证未执行。开发库迁移及分类索引漂移修复证据见实施计划。
- 日期：2026-10-13。
- 范围：补充 ADR 0018 的微信身份及 ADR 0019 的统一消费者契约。
- 实施：[原全栈计划](../../plans/2026-10-13_小程序手机号统一登录与第三方身份接入计划.md)。

## 背景

用户确认小程序以微信身份自动识别和建号，手机号作为当前账户的独立已验证资料。首次授权后日常恢复不重复收集手机号，公开浏览保持可用。

## 决策

1. UUID user_id 为不变商城主键，wx_ 随机用户名保持独立，password_hash 为空；OpenID 不作为用户名。后台按已登记 AppID 换码，未知身份在注册开关允许时自动建号。
2. 手机号独立保存在 users，使用 E.164、验证时间和来源的一致性约束及全局唯一约束。只绑定当前有效微信账户，不通过手机号切换账户，不自动合并数据。同号占用或换号请求拒绝。
3. 复用 user_external_identities 的两个唯一约束，增加可信开放平台命名空间用于 UnionID 记录。当前只接入单一 AppID，UnionID 不自动归并；第二应用开放前先解决跨应用联合身份唯一映射。
4. 基础身份允许读取本人资料、绑定手机号、退出及账户安全操作。购物、地址、交易、会员、推荐、积分和资金入口要求已验证手机号，拒绝使用独立 PHONE_BINDING_REQUIRED，不能等同 Token 失效。
5. 用户主动同意相关隐私处理后可恢复微信身份；无同意的首次公开浏览不强制认证。用户主动退出后停止自动恢复。手机号和资料组件由用户主动触发，昵称头像可跳过。
6. 手机号换码使用官方稳定凭据接口及手机号接口。应用凭据按 AppID 缓存；code 摘要单次消费且有 TTL，超时不重放。最终手机号与成功安全事件在 PostgreSQL 事务提交，响应丢失由本人资料查询确认。
7. 客户端返回意图仅内存保存 15 分钟，路由及参数白名单；商品恢复原规格数量后再确认操作。凭据不进入返回 URL 或持久存储。

## 后果和开放条件

本期不增加业务表，不扩展 Admin 密码或用户名规则。新增迁移只增加可空字段，历史账户不伪造手机号。手机号记录写入后不得直接破坏性降级；关闭能力并前向修复。

手机号对指定功能的必要性、主体资格、费用额度、隐私声明、HTTPS 域名和服务端出口须在实际开放前确认。默认登录关闭，静态门禁不证明微信平台可用。测试源码覆盖身份分层、官方响应、一次性凭据与真实 PostgreSQL 同号竞争；执行遵守项目显式授权规则。
