# 消费者接口统一与浏览器认证退役决策

- 状态：已确认并实施源码
- 日期：2026-10-09
- 决策者：大仙
- 实施：[消费者接口与认证统一计划](../../plans/2026-10-09_消费者接口与认证统一计划.md)
- 当前机制：[认证与授权](../architecture/authentication-authorization.md)

## 背景

本项目的唯一 C 端是微信小程序。按客户端划分的路由重复声明地址、购物车、下单等动作，增加契约与认证维护成本。用户确认将消费者能力并入原业务模块，并退役旧消费者浏览器认证。

## 决策

1. 消费者只使用微信登录和 Bearer 会话。`/auth` 承接换码、刷新、退出与登录能力查询；`/users/me` 承接本人资料、头像、会话、积分及只读注销核对。旧密码注册、登录、改密、直接注销和浏览器注册能力端点退役。
2. 地址、购物车、报价、订单、退款、履约、推荐与资金查询按既有业务路径合并。移除全部 `/api/v1/miniapp` 路由，不保留别名、重定向或双轨业务入口。订单列表与详情统一返回本人展示投影，保留原请求恢复查询。
3. 统一 `get_current_user` 使用 `ConsumerBearer`，拒绝 Cookie 与混合凭据，校验签名、audience、用户状态、凭据版本、会话 Profile、客户端、撤销与期限；数据库故障返回 503。不存在先失败再尝试另一种身份的回退。
4. Admin 继续使用独立 Cookie、Origin、CSRF、准确权限与事务内审计。通用资产上传只面向 Admin；消费者头像在本人资料入口固定 avatar 场景。Bearer 不授予管理权限。
5. 查询保留本人过滤和字段白名单；明确集合撤销、原目标状态查询、未知写结果恢复、no-store 和敏感日志保护随业务迁移。实际注销、新提现申请和真实资金渠道仍关闭。
6. 已存储的 `miniapp_bearer`、`pinjie-miniapp`、历史审计事件、`MINIAPP_*` 配置及微信建号设置保留其语义。历史 Cookie 会话不转换、不删除，也不能访问消费者接口。本次无数据库结构变更，不改历史迁移。

本决策替代 ADR 0010 的消费者 Browser Cookie 入口与 ADR 0018 的客户端专属路由决策；微信可信身份、独立密钥、会话安全和内容边界继续有效。

## 交付与回滚

Backend、唯一 OpenAPI、生成客户端与小程序调用必须配套交付。旧消费者版本调用已退役端点会明确失败，不能与新后端混用。已批准的破坏性差异按仓库契约例外流程逐项登记，基线推进后删除，禁止永久例外。

发布前验证目标环境已满足既有身份模型迁移与配置条件；本次不执行迁移或部署。回滚需协调恢复同一版本的后端和小程序，不转换用户身份或回退数据库数据。历史浏览器配置项与管理设置保留，不代表浏览器认证仍开放。

## 验证边界

本次运行后端静态门禁、契约导出和生成、Admin/Miniapp 类型及 Lint、文档治理。测试源码覆盖凭据隔离、会话边界、旧路由退役与既有查询恢复；pytest、Vitest、构建、真实微信、数据库与并发动态验证按项目策略未执行。
