# ADR 0016: 独立商城基线与 Web 停用决策

- 状态：已确认
- 日期：2026-09-16
- 决策者：大仙
- 关联计划：[独立商城基线校正计划](../../plans/2026-09-16_独立商城基线校正计划.md)

## 背景

项目需要作为独立商城持续开发和发布。此前工程中保留了历史 Web 服务、三端发布编排和外部仓库发布身份，这与微信小程序为唯一 C 端、当前阶段只建设 Backend 与 Admin 的边界冲突。

## 决策

1. `pinjie-mall` 独立维护代码、配置、镜像、发布凭据和部署记录，不使用其他仓库的运行路径、发布仓库、密钥仓库或镜像命名空间。
2. 微信小程序是唯一 C 端形态。当前阶段不创建小程序工程，Backend 契约为后续小程序提供服务。
3. `apps/web` 作为历史骨架冻结保留。其开发、构建、启动和测试命令必须明确失败；生产 Compose、镜像发布、部署和 E2E 不得包含 Web 服务或 Web 端口。
4. 日常和生产容器只交付 Backend 与 Admin。服务端口固定为 Backend 18168 和 Admin 3001；3000 及其他 Web 端口禁止监听或暴露。
5. 项目身份、需求、发布和运行文档以独立商城事实为准。历史提交仍由 Git 历史追溯，不作为当前工程依赖。

## 后果

- 运营后台和后端可继续独立推进，商城核心业务与小程序端在后续计划中衔接。
- 已冻结的 Web 源码不会作为可运行交付物，恢复任何 Web 能力都需要新的全栈计划和明确用户授权。
- CNB、TCR 和部署环境需要由商城维护者配置独立资源；缺失时发布必须失败，不能回退到其他仓库资源。
