# 小程序独立身份会话与内容边界决策

- 状态：已确认并实施源码
- 日期：2026-10-09
- 决策者：大仙
- 实施：[身份与基础交易接入计划](../../plans/2026-10-09_小程序身份与基础交易接入计划.md)
- 当前机制：[认证与授权](../architecture/authentication-authorization.md)、[小程序工程标准](../architecture/miniapp-engineering-standard.md)

## 背景

微信小程序需要独立消费者身份与交易入口。既有 Browser Cookie Profile、密码用户和 Admin 权限继续保留，微信凭据不进入浏览器链路。商品说明已有 Tiptap HTML 和未经审计的历史字符串。

## 决策

消费者浏览器认证与第 2 项中的专属路由选择已由 [ADR 0019](0019-消费者接口统一与浏览器认证退役决策.md)替代；以下保留原决策记录，微信身份、会话与内容边界继续有效。

1. 微信一次性 code 只由服务端向固定微信接口换取可信 OpenID。以 provider、AppID、OpenID 的唯一绑定识别账户，并发首次建号取得身份事务锁；无密码账户独立创建，不根据客户端昵称、手机号或 UnionID 自动合并。首次建号由固定 miniapp_registration 设置控制，共享配置锁与关闭操作确定先后顺序。
2. /api/v1/miniapp 使用独立 miniapp_bearer、pinjie-miniapp audience、JWT/HMAC 密钥和准确 Bearer 安全声明，拒绝 Cookie。UserSession 的 Profile、client_id 和 csrf_digest 使用成组约束；存量 Cookie 入口保持准确隔离。未启用登录时明确返回不可用，缺失已启用能力的配置拒绝启动。
3. Access/Refresh 只在客户端私有内存。刷新单飞、单次轮换，重放撤销原会话与 Refresh 族；服务端每次检查会话、用户和凭据版本。用户同意隐私说明后可登录，冷启动取得新的微信 code 恢复；主动退出后不自动登录。只持久化非秘密偏好和按本人隔离的最小结算恢复记录。
4. 写请求无通用重试或离线恢复。下单先保存原 request_id、商品、地址 ID 和报价指纹；结果未知时只查询本人原请求或由用户显式以完全相同内容恢复。价格、库存、零元成交和取消竞争沿用现有服务端裁决。
5. 新商品说明严格校验并规范化受限 HTML v1。使用 html5lib 标准解析器，允许段落、列表、标题、强调与经验证的文字颜色，拒绝脚本、链接、媒体、事件和额外样式。媒体继续使用独立图集，客户端使用 mp-html 原生组件且关闭链接复制与锚点导航。

## 历史内容迁移窗口

遵守 [ADR 0007](0007-受控迁移兼容策略决策.md)。负责人 jinmozhe，开始 2026-10-09，删除日期 2026-10-23，消费者为 Admin 与 Miniapp。旧说明 description_version=0 明确标记 legacy，公开响应不返回旧内容；新写与完成迁移的内容为 1。该标记只用于审计迁移，不能按字符串自动猜测或建立永久双读。

工具明确要求指定商品 ID 与 text/html 来源，默认 dry-run；整批校验成功后才允许显式 apply。观测为 legacy 商品数量、迁移校验失败数量和 v1 内容校验错误。结束条件为目标数据审计完成、legacy 数量为零，再在后续受控变更删除 legacy 分支与格式窗口并增加只允许 v1 的删除测试。逾期需明确重新决策，不能默认延期。

回滚先暂停新内容写入并核查数据；数据库 downgrade 遇到 Bearer 会话或 v1 商品明确拒绝，禁止自动删数据。未审计内容继续不公开渲染。工具和新 revision 已提供，实际数据迁移未执行。

## 验证与限制

本轮仅执行适用轻量门禁和契约生成；安全、会话、内容和真实 PostgreSQL/Redis 回归测试源码已补充，pytest/Vitest 未执行。AppID、服务端秘密、数据库升级、权限目录同步、微信工具、真机、真实渠道和发布需要各自前置条件与适用授权。源码实现不代表真实登录或交易验收通过。
