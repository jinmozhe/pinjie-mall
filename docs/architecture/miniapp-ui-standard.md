# 微信小程序 UI 与交互规范

## 1. 范围与视觉方向

本文是微信商城首版的视觉 tokens、组件、页面结构和状态验收标准，适用于后续 `apps/miniapp`。需求边界以[小程序 PRD](../MINIAPP_PRD.md)为准，依赖和单位实现以[工程标准](miniapp-engineering-standard.md)为准。本文已定版，V1 视觉风格已获用户确认，完整页面与关键状态已有[静态设计图集](../design/miniapp/README.md)；公开浏览组件已实现，扩展交易流程与微信工具/真机视觉验收未完成。

默认采用简洁、明亮的商品展示与购物流程：白色内容面、浅灰背景、深红主操作、清晰价格层级、紧凑但可点击的列表。商品图片作为主要视觉，不用大面积渐变、玻璃效果、厚阴影和多层嵌套卡片。此方向是首版默认标准，不修改既有 Admin，不虚构品牌标识或促销能力。

UI 使用 NutUI React-Taro 与微信原生组件。组件外观统一经 tokens 和主题变量调整，不将 NutUI 示例皮肤当作另一套设计标准，不使用 DOM 组件库。

## 2. 设计宽度与尺寸

设计稿宽度固定 750，基准预览为 375 逻辑像素。下文尺寸均为目标 rpx；业务 Sass 用同数值 px 经 Taro 750 规则转换。NutUI 375 源样式单独换算，不复制其原始 px 数值到业务 tokens。

| 类别 | token/语义 | 标准值 | 使用方式 |
| --- | --- | --- | --- |
| 间距 | space-1/2/3/4/5/6/8 | 8/16/24/32/40/48/64 rpx | 页面与组件沿用同一间距序列 |
| 页面 | page-padding | 32 rpx | 主内容左右留白；详情连续图集可全宽 |
| 内容 | section-gap/card-padding | 24/24 rpx | 区块间距与卡片内距，避免卡片包卡片 |
| 字号 | caption/body/section/title | 24/28/32/36 rpx | 辅助、正文、区块标题、页面标题 |
| 价格 | price-main/price-secondary | 44/32 rpx | 商品主价格、购物车/订单金额；货币符号可 28 rpx |
| 行高 | line-height | 1.5 | 长文说明与错误提示不固定高度裁切 |
| 字重 | regular/medium/semibold | 400/500/600 | 金额和主要标题 600，不依赖下载字体 |
| 圆角 | radius-control/card/sheet | 12/20/24 rpx | 控件、卡片、底部弹层上角；药丸仅用于短标签 |
| 点击 | touch-min | 88 × 88 rpx | 图标、复选框扩大容器点击区，视觉尺寸可较小 |
| 按钮 | button-height | 88 rpx | 主要和次要按钮同高，文字 28 rpx |
| 图标 | icon-default | 40 rpx | TabBar 图标 48 rpx，不混用不同线宽体系 |
| 商品图 | thumb/cart-image | 1:1 / 160 rpx | 列表主图等比裁切，详情主图保持完整内容 |

字体使用微信平台系统字体，不加载远程字体。边框使用明确物理 1px 或经核验的细线策略；不把所有 1px 全局替换为 rpx。阴影默认无，必要的固定底栏可用细分隔线，弹层使用单一遮罩。

## 3. 颜色 tokens

| token | 值 | 用途 |
| --- | --- | --- |
| color-primary | #B42318 | 主按钮、选中规格边框、关键操作与主价格 |
| color-primary-pressed | #912018 | 点击反馈，不依赖 hover |
| color-primary-soft | #FFF1EF | 选中规格/轻提示底色 |
| color-background | #F7F8FA | 页面背景 |
| color-surface | #FFFFFF | 卡片、表单、弹层和导航内容面 |
| color-text | #1D2939 | 正文、名称和重要信息 |
| color-text-secondary | #475467 | 说明、标签、次级信息 |
| color-text-disabled | #98A2B3 | 禁用控件，不能用于必须阅读的正文 |
| color-border | #E4E7EC | 分隔线与未选中控件边框 |
| color-success | #16794A | 已确认成功事实 |
| color-warning | #8A4B08 | 待确认、未知结果与业务提示 |
| color-danger | #B42318 | 错误、删除和不可逆风险 |
| color-info | #175CD3 | 查询说明与信息链接 |

主按钮文字白色，选中规格为主色文字/边框配浅色背景。危险动作与正常购买通过文案、图标和确认步骤区分，不能仅靠红色表达语义。状态标签必须含文字，不向未知支付或审核通过状态使用“成功”样式。

实现时 tokens 集中于 `src/styles/`，组件消费语义名称，不在页面写散落色值。金额仅按后端给定币种和十进制字符串格式化，禁止客户端自行四舍五入决定应付。

## 4. 通用组件标准

| 组件 | 布局与交互要求 |
| --- | --- |
| 导航/TabBar | 首版使用系统导航与原生 TabBar，四项为首页、分类、购物车、我的；不重复占用原生导航空间 |
| 主按钮 | 单一主要动作；提交中保留原标签与加载反馈，禁用重复点击；次要动作使用描边或文本样式 |
| 商品卡片 | 首页/分类可用两列，购物车/订单用单列；名称最多两行，价格与辅助价分层，整体点击区不重叠 |
| SKU 弹层 | 图片、名称与价格摘要、规格分组、数量、确认按钮；不可售选项显示原因并禁止选择；高内容区滚动，底部动作固定 |
| 数量控件 | 按服务端约束设置范围，支持键盘输入核验；输入未确认时不连发请求；冲突后重读并明确提示 |
| 表单 | 标签和输入可辨认，错误就近显示；不以 placeholder 代替标签；键盘出现时当前输入和保存动作可达 |
| 确认弹窗 | 删除地址/条目、取消订单等动作说明目标、后果与按钮语义；取消为安全退出，不把授权弹窗包装成营销提醒 |
| Toast/提示 | 短反馈不承载关键资金结果；支付未知、报价变化与失败恢复用持久内容和可操作入口 |
| 状态/空态 | 图标可选，优先一句原因与一个适用动作；加载、无数据、筛选无结果、请求失败、未登录分别呈现 |
| 富文本 | 渲染工程标准允许的内容；说明正文保持可读，颜色不合规由内容治理处理，不覆盖为另一套随机主题 |
| 图片 | 固定比例占位，失败提供重试；商品详情切片等宽无缝，图片预览不覆盖支付/提交中的关键确认 |

购物车角标口径统一为本人购物车全部条目的 quantity 合计，包含需用户处理的失效条目；不是已选商品数量或条目数。底层查询未就绪时不伪造 0，已有值刷新失败时保留并提示刷新状态。显示上限为 `99+`，数值从同一 Query 派生，不在 Store 维护副本。

## 5. 核心页面结构

| 页面 | 从上到下的主要结构 | 行为边界 |
| --- | --- | --- |
| 首页 | 商城名称/基础信息、分类入口、公开商品列表 | 不预设轮播装修、搜索框、秒杀或优惠券入口 |
| 分类 | 一级导航、必要下级入口、分页商品列表 | 类别切换由服务端过滤并重置分页，窄屏不能挤压商品点击区 |
| 商品详情 | 主图、名称与参考价、规格入口、允许的富文本、独立详情切片、评价、底部购物动作 | 实物/虚拟及不可售原因可见，不能自行推算会员价或承诺库存 |
| 购物车 | 条目、失效原因、数量与选择、底栏汇总/去结算 | 合计非成交承诺，结算必须重新报价；删除有确认 |
| 结算 | 实物地址或虚拟交付说明、商品、运费与金额、报价变化提示、提交动作 | 混合商品类型拒绝；零应付展示内部成交流程，不调支付 |
| 订单列表/详情 | 状态与筛选、快照、金额、履约、支付/售后事实、当前允许操作 | 分页和全量统计来自服务端；未提供接口不伪造筛选与数量 |
| 售后 | 资格与整单退款说明、申请、审核和渠道退回进度 | 审核通过不显示到账，不提供本期不支持的部分退款 |
| 我的 | 登录/账户摘要、订单与地址入口、会员分销、帮助/隐私/退出 | 私有内容鉴权加载，未接通能力不呈现可执行资金入口 |
| 分销钱包 | 资格、推荐关系、佣金记录、两类钱包、提现状态 | 金额采用后端事实，保留消费/提现权利和欠款限制 |

首页和商品列表不为了视觉添加超出 PRD 的业务能力。可执行功能缺失时明确说明适用条件，不能用演示数据充当真实业务内容。

## 6. 状态与反馈文案

| 状态 | 展示 | 可执行动作 |
| --- | --- | --- |
| 首次加载 | 稳定布局的骨架/加载提示，禁止闪现“空购物车” | 等待，必要时取消当前页面 |
| 查询失败 | “加载失败，请重试”，保留适用追踪标识入口 | 重试查询，不重放交易写入 |
| 未登录 | “登录后查看购物车/订单”，公开浏览保持可用 | 用户发起登录，完成后恢复上下文 |
| 写成功、后续查询失败 | “已加入，购物车刷新失败” | 刷新购物车，不能诱导再加一次 |
| 报价变化 | 展示最新金额与需要重新确认的原因 | 用户确认最新报价后再提交 |
| 下单/支付未知 | “结果确认中，请稍后查询” | 查询订单，保留相同业务意图 |
| 支付弹窗返回 | “正在确认付款结果” | 查询 Backend，不显示已支付承诺 |
| 退款审核通过 | “审核通过，退款处理中” | 查询渠道资金结果 |
| 停用/撤销 | 明确会话失效与适用说明，清理私有内容 | 重新登录或联系运营 |

任何状态不能只用颜色、动画或短 Toast 表示。资金结果未确认时禁止绿色成功页、到账金额变化和重复支付按钮。失败反馈只出现必要信息，不展示后端堆栈、Token、OpenID 或完整收款资料。

## 7. 安全区、响应与动效

- 底部动作区使用平台安全区尺寸，正文预留实际底栏加安全区高度；使用原生 TabBar 的页面不重复补一份 TabBar 占位。
- SKU 弹层最大高度为可用视口的 80%，中部内容滚动；顶部关闭和底部确认保持可达，键盘与安全区不遮挡金额。
- 在 320、375、414 逻辑像素宽度以及适用的更宽微信窗口核对长标题、两列卡片和横向溢出；文字增大不能造成按钮不可达。
- 重要金额不截断，长商品名称可折行或省略并通过详情查看；手机号和地址按隐私策略展示。
- 原生控件、相机/图片预览和弹层层级按微信实际渲染核对，不用任意超大 z-index 代替平台适配。
- 仅保留必要的点击、加载和弹层动效，常规过渡 160 至 240 ms；不使用自动轮播、收益跳动、长时间闪烁或大幅位移动画。

## 8. 设计交付与视觉验收

后续页面设计与实现先套用本文 tokens，再落组件。页面原型覆盖首页、分类、商品详情/SKU、购物车、结算、订单、售后和我的；每页至少包含正常、加载、空态、失败及适用的未登录/未知结果状态。

在明确授权的微信工具与 iOS/Android 真机验收中检查：点击区、字体和颜色对比、长文本、图片失败、键盘、安全区、横向溢出、弹层滚动、重复提交保护、前后台恢复、支付返回和账户隔离。普通文字对比目标至少 4.5:1，大字号至少 3:1；状态还须有文字或图标辅助。仅静态规范或截图不算交互与资金验收。

页面设计资产统一维护在 `docs/design/miniapp/`，已有核心与全套状态图。当前公开浏览按确认的风格直接落地可编辑 Taro 页面，交互源文件位于 apps/miniapp/src；独立 HTML/CSS 业务原型未生成，后续按需作为离线设计资料制作，不启动 Web 服务、不进入冻结的 apps/web，也不代替微信端验收。

当前保留已确认风格的 V1 核心页面图，并已按 PRD 与后端现有能力扩展 V2 全页面和关键状态；具体范围以设计目录为准。尚未初始化 tokens 或组件代码，未完成扩展流程确认、业务交互原型与真机验收。后续品牌调整集中修改 tokens 与适用设计说明，不同时维护另一套页面配色。
