# 微信小程序 UI 与交互规范

## 1. 范围与视觉方向

本文是微信商城首版的视觉 tokens、组件、页面结构和状态验收标准，适用于 apps/miniapp。需求边界以[小程序 PRD](../MINIAPP_PRD.md)为准，依赖和单位实现以[工程标准](miniapp-engineering-standard.md)为准。V1 风格已确认，完整页面与关键状态已有[静态设计图集](../design/miniapp/README.md)；公开浏览和身份/地址/购物车/结算/基础订单页面已有源码，微信工具及真机视觉验收未完成。

默认采用简洁、明亮的商品展示与购物流程：白色内容面、浅灰背景、深红主操作、清晰价格层级、紧凑但可点击的列表。商品图片作为主要视觉，不用大面积渐变、玻璃效果、厚阴影和多层嵌套卡片。此方向是首版默认标准，不修改既有 Admin，不虚构品牌标识或促销能力。

UI 使用 NutUI React-Taro 与微信原生组件。组件外观统一经 tokens 和主题变量调整，不将 NutUI 示例皮肤当作另一套设计标准，不使用 DOM 组件库。

小程序功能图标统一使用 NutUI，`@nutui/icons-react-taro` 为唯一功能图标库；禁止混用其他功能图标库或新增 SVG、CSS、字符绘制的功能图标。页面经 `components/Icon` 的显式图标集合引用，名称由 TypeScript 校验；颜色继承现有语义 tokens，尺寸统一使用 rpx，默认 40 rpx。优先使用无 F 后缀的线性图形，微信标识沿用库内形状。装饰图标不重复朗读，纯图标按钮在父控件提供操作标签；不改变原按钮点击区、禁用及加载行为。原生平台控件仍使用系统图形。

原生 TabBar 从同一 NutUI 图形生成普通态和选中态 PNG，清单及颜色由 `src/tab-bar.json` 管理，不单独绘制第二套图标。会员、积分、佣金、隐私分别使用 User、Star、Prices、ShieldCheck；图形含义依靠原有文字补充，保留服务入口颜色和背景。店铺插画、账户背景、分享封面、商品图片、用户头像及后台配置的分类图片保持原来源，不归入功能图标替换。

## 2. 设计宽度与尺寸

设计稿宽度固定 750，基准预览为 375 逻辑像素。下文尺寸均为目标 rpx；业务 Sass 用同数值 px 经 Taro 750 规则转换。NutUI 375 源样式单独换算，不复制其原始 px 数值到业务 tokens。

| 类别 | token/语义 | 标准值 | 使用方式 |
| --- | --- | --- | --- |
| 间距 | space-1/2/3/4/5/6/8 | 8/16/24/32/40/48/64 rpx | 页面与组件沿用同一间距序列 |
| 页面 | page-padding | 32 rpx | 主内容左右留白；详情连续图集可全宽 |
| 内容 | section-gap/card-padding | 24/24 rpx | 区块间距与卡片内距，避免卡片包卡片 |
| 字号 | caption/body/section/title | 24/28/32/36 rpx | 辅助、正文、区块标题、页面标题 |
| 价格 | price-main/price-secondary | 44/32 rpx | 商品主价格、购物车/订单金额；货币符号可 28 rpx |
| 行高 | line-height | 1.5 | 长文说明与错误提示不固定高度裁切 |
| 字重 | regular/medium/semibold | 400/500/600 | 金额和主要标题 600，不依赖下载字体 |
| 圆角 | radius-control/card/sheet | 12/20/24 rpx | 控件、卡片、底部弹层上角；药丸仅用于短标签 |
| 点击 | touch-min | 88 × 88 rpx | 图标、复选框扩大容器点击区，视觉尺寸可较小 |
| 按钮 | button-height | 88 rpx | 主要和次要按钮同高，文字 28 rpx |
| 图标 | icon-default | 40 rpx | TabBar 图标 48 rpx，不混用不同线宽体系 |
| 商品图 | thumb/cart-image | 1:1 / 160 rpx | 列表主图等比裁切，详情主图保持完整内容 |

字体使用微信平台系统字体，不加载远程字体。边框使用明确物理 1px 或经核验的细线策略；不把所有 1px 全局替换为 rpx。阴影默认无，必要的固定底栏可用细分隔线，弹层使用单一遮罩。

主按钮文字白色，选中规格为主色文字/边框配浅色背景。危险动作与正常购买通过文案、图标和确认步骤区分，不能仅靠红色表达语义。状态标签必须含文字，不向未知支付或审核通过状态使用“成功”样式。

实现时 tokens 集中于 `src/styles/`，组件消费语义名称，不在页面写散落色值。金额仅按后端给定币种和十进制字符串格式化，禁止客户端自行四舍五入决定应付。

## 4. 通用组件标准

| 组件 | 布局与交互要求 |
| --- | --- |
| 导航/TabBar | 首版使用系统导航与原生 TabBar，四项为首页、分类、购物车、我的；不重复占用原生导航空间 |
| 主按钮 | 单一主要动作；提交中保留原标签与加载反馈，禁用重复点击；次要动作使用描边或文本样式 |
| 商品卡片 | 首页双列，分类左图右文单列，购物车/订单用单列；名称最多两行，价格与辅助价分层，整体点击区不重叠 |
| SKU 弹层 | 图片、名称与价格摘要、规格分组、数量、确认按钮；不可售选项显示原因并禁止选择；高内容区滚动，底部动作固定 |
| 数量控件 | 按服务端约束设置范围，支持键盘输入核验；输入未确认时不连发请求；冲突后重读并明确提示 |
| 表单 | 标签和输入可辨认，错误就近显示；不以 placeholder 代替标签；键盘出现时当前输入和保存动作可达 |
| 确认弹窗 | 删除地址/条目、取消订单等动作说明目标、后果与按钮语义；取消为安全退出，不把授权弹窗包装成营销提醒 |
| Toast/提示 | 短反馈不承载关键资金结果；支付未知、报价变化与失败恢复用持久内容和可操作入口 |
| 状态/空态 | 图标可选，优先一句原因与一个适用动作；加载、无数据、筛选无结果、请求失败、未登录分别呈现 |
| 富文本 | 渲染工程标准允许的内容；说明正文保持可读，颜色不合规由内容治理处理，不覆盖为另一套随机主题 |
| 图片 | 固定比例占位，失败提供重试；商品详情切片等宽无缝，图片预览不覆盖支付/提交中的关键确认 |

购物车角标口径统一为本人购物车全部条目的 quantity 合计，包含需用户处理的失效条目；不是已选商品数量或条目数。底层查询未就绪时不伪造 0，已有值刷新失败时保留并提示刷新状态。显示上限为 `99+`，数值从同一 Query 派生，不在 Store 维护副本。

## 5. 核心页面结构

| 页面 | 从上到下的主要结构 | 行为边界 |
| --- | --- | --- |
| 首页 | 商城名称/基础信息、2×4 八宫格一级分类入口卡片、公开全部商品列表 | 取服务端启用的一级分类前 8 项，白色圆角卡片内 4 列 × 2 行展示 `104×104 rpx` 彩色分类图标与名称；点击通过 `switchTab` 跳转到“分类”Tab 页并定位选中该类目；不预设轮播装修、搜索框、秒杀或优惠券入口 |
| 分类 | 固定搜索、左侧一级导航、右侧范围与按需二三级筛选、单列商品及触底加载 | 服务端名称搜索与分类组合，切换条件重置分页；首页分类入口清除旧搜索并定位，详情返回保持浏览位置；商品卡和加号统一进入详情 |
| 商品详情 | 主图、名称与参考价、规格入口、允许的富文本、独立详情切片、评价、底部购物动作 | 实物/虚拟及不可售原因可见，不能自行推算会员价或承诺库存 |
| 购物车 | 有商品时展示条目、失效原因、数量与选择、底栏汇总/去结算；未绑定及空车正文仅显示图标与单一按钮 | 未登录或未绑定手机号显示“登录”，已绑定且查询确认为空显示“再逛逛”；合计非成交承诺，结算必须重新报价；删除有确认 |
| 结算 | 实物地址或虚拟交付说明、商品、运费与金额、报价变化提示、提交动作 | 混合商品类型拒绝；零应付展示内部成交流程，不调支付 |
| 订单列表/详情 | 状态与筛选、快照、金额、履约、支付/售后事实、当前允许操作 | 分页和全量统计来自服务端；未提供接口不伪造筛选与数量 |
| 售后 | 资格与整单退款说明、申请、审核和渠道退回进度 | 审核通过不显示到账，不提供本期不支持的部分退款 |
| 我的 | 与个人资料共用几何背景、头像昵称与三项资产摘要、五项订单入口、十二宫格服务、品牌页脚 | 未绑定手机号显示未登录；本人余额按服务端事实展示，原生 TabBar 保留 |
| 个人资料 | 红色几何背景、白色卡片、圆形头像与相机、昵称输入、按进入方式显示保存按钮和底部导航 | 头像选择后即时更新；首次绑定显示保存并继续与暂时跳过，均返回原目标；普通进入显示保存更新 |
| 会员中心 | 自动建立的基础档案、等级有效状态、推荐关系是否已绑定 | 不提供手动开通；基础建账不保证等级或收益，不展示他人身份，不自动绑定推荐人 |
| 推荐与分享 | 本人邀请码、复制/原生分享、已有绑定时间、推荐码输入及确认、未知结果查询与原码恢复 | 分享参数仅为意图，不自动绑定；关系不能换绑，固定封面无账户数据，不承诺奖励 |
| 我的积分 | 账户是否建立、可用/冻结/追回欠款、分页流水与三类变化 | 精确字符串展示；账户未建立与真实空流水区分，不提供兑换/抵扣/到期操作 |
| 分销钱包 | 资格、推荐关系、佣金记录、两类钱包、提现状态 | 金额采用后端事实，保留消费/提现权利和欠款限制 |

上述资料与会员资金页面已有源码。钱包按轨道展示可用、冻结和欠款，流水分开显示三类变动及历史余额快照；佣金显示冻结/结算/追回，提现历史分开显示审核、人工确认与渠道确认。没有资金确认事实时保留查询与帮助入口，新申请不提供操作。页面沿用现有 tokens、安全区与可换行金额，微信视觉和交互验收未执行。

首页和商品列表不为了视觉添加超出 PRD 的业务能力。可执行功能缺失时明确说明适用条件，不能用演示数据充当真实业务内容。

分类页使用原生标题及 TabBar，正文不重复大标题。搜索框采用浅灰底、12 rpx 圆角与至少 88 rpx 高度，NutUI Search/Close 图标；输入后明确提交查询，结果区持续展示分类路径、已提交关键词及服务端总数。左栏宽 176 rpx、浅灰底，选中为白底深红文字与左侧指示条；长分类名可换行。下级分类只在存在时展示，切换父级清除后代，全部商品首项不带分类参数。

右侧白底商品行使用 160 rpx 方图、28 rpx 两行标题、24 rpx 类型/规格提示及 32 rpx 深红价格，金额可换行，参考价独立一行。仅唯一可展示 SKU 且 market_price 高于其 price 时显示划线价，避免跨规格配价；不截取 HTML 说明作摘要、不推算会员价或库存。红色加号视觉 56 rpx、点击区 88 rpx，操作标签为查看商品详情，与商品卡行为一致，跳转防重复并提供失败提示。

左右独立滚动，右侧触底加载且失败保留商品，前序窗口可向上重取；列表起点支持下拉刷新，底部保留刷新入口。首次加载、分类不可用、空商品、搜索无结果、网络等待及分页失败分别表达；分类内无结果提供“在全部商品中搜索”和“清空搜索”，不自动扩大范围。窗口替换保留可见商品位置，具体缓存规则见工程标准；键盘、窄屏、长列表及平台滚动仍需独立微信验收。

购物车两种空态保留原生标题与 TabBar，浅灰正文居中展示 NutUI Cart 图标、浅暖色圆形底与红色圆角主按钮，不重复标题，不显示其他说明、商品计数或结算底栏。颜色由 `cart-empty-*` tokens 维护，图标按需引用，不新增位图资源。“登录”调用统一认证并恢复购物车，“再逛逛”返回首页；跳转失败以原生弹窗反馈并允许重试。查询加载及失败继续使用独立状态，不伪装为空车。

## 6. 状态与反馈文案

### 统一登录页

`subpackages/account/auth/index` 使用已确认的暖白底色、红色主操作和店铺插画。页面提供微信登录、暂不登录、同意勾选、《用户协议》与《隐私条款》，采用 navigationStyle=custom，自绘透明返回按钮和“登录”标题；右侧微信胶囊、状态栏与底部系统手势条继续由系统显示。背景独立固定到视口顶部，覆盖状态栏和导航区域，无额外顶部留白或独立纯色导航条；正文在导航以下独立滚动，底部保留安全区。顶部返回复用暂不登录的安全取消路径，处理中禁止重复返回。无重复首页入口、手机号用途常驻提示或勾选引导文字/箭头；错误反馈仍就近展示。首次手机号绑定确认成功进入个人资料引导，完成或跳过后恢复原目标；已有绑定的日常登录直接返回。

登录与个人资料共用 useNavigationLayout，根据实际状态栏和胶囊尺寸计算导航高度及标题两侧避让；进入、恢复显示及窗口尺寸变化时重新读取，读取异常展示重试与返回入口。背景不增加状态栏 padding，安全间距只用于导航和前景内容。微信官方依据见[页面配置](https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/page.html)与[胶囊布局信息](https://developers.weixin.qq.com/miniprogram/dev/api/ui/menu/wx.getMenuButtonBoundingClientRect.html)。

登录专用颜色集中维护于 `src/styles/tokens.scss` 的 `auth-*` tokens，不改变其他业务页面。背景图形使用 CSS，店铺插画保留本地 SVG；微信标识、返回、勾选与关闭使用公共 NutUI 图标。标题优先使用设备已有楷体，无适用字体时使用系统衬线字体，不加载字体包，因此不同设备字形可能不同。

协议勾选和完整协议文案作为独立底栏，置于正文 ScrollView 之外，固定在全屏布局底部，不随正文滚动。底部保留 36 rpx 留白并叠加系统安全区；底栏不收缩，文案换行时按实际高度占位，上方滚动区自动让出空间，不遮挡登录、暂不登录或错误提示。

两个协议使用 NutUI 底部弹层，正文由 ScrollView 滚动，顶部关闭与底部关闭按钮保持可达，底部补安全区。隐私正文通过 privacy Feature 公开入口复用完整说明，不附加该页面之外的帮助或注销按钮；阅读和关闭不自动勾选同意。

协议 Popup 始终放在独立的 auth-legal-host View 中，使遮罩与弹窗作为该容器内的相邻节点，隔离关闭后重新打开时的节点位置更新。容器不设置 transform、定位或裁切，不改变弹窗和遮罩的全屏定位。保留关闭动画和每次打开时的正文滚动重置；重复打开同一协议、交替打开两种协议及关闭动画期间重新打开均需微信端验收，遮罩节点不得包含协议标题、正文或关闭按钮。

启动静默识别微信身份，不在此阶段请求手机号或弹出协议。未勾选时登录按钮不可提交；勾选后点击“微信登录”直接触发 getPhoneNumber 与 agreePrivacyAuthorization 组合原生能力，不切换为第二个“授权手机号并继续”步骤。身份请求尚在进行时展示加载，失败后可在同一次手机号回调中恢复身份再绑定。手机号选择及更换号码界面由微信控制，不绘制虚假手机号弹窗。已绑定用户正常恢复时不重复授权；仅需基础身份的账户安全目标不索取手机号。绑定结果不明时同一按钮改为查询，只有查询后才能重新取得新授权凭证；错误就近展示。真实平台样式、字体、授权和窄屏表现须在获授权的微信验收中核实。

### 个人资料页

`subpackages/account/profile/index` 使用 navigationStyle=custom，由同一张本地 SVG 几何背景覆盖全屏，背景使用 fixed 固定到视口 top=0，顶部红色渐变为下方暖白。自绘白色返回箭头与标题，导航区域透明，无单独纯色底、边框或阴影；保留微信系统状态栏和右侧原生胶囊，不绘制或隐藏系统控件。通过 getWindowInfo 的状态栏高度和 getMenuButtonBoundingClientRect 的实际矩形布局，标题两侧对称避让胶囊，进入、恢复显示及窗口变化时重新读取；读取异常显示重试，不能用虚构设备尺寸掩盖问题。固定顶部之外的内容使用独立 ScrollView，包含权限拦截、加载和错误状态，避免正文滚动覆盖胶囊。

白色资料卡片无多层嵌套。圆形头像与相机按钮整体可点击，空头像使用公共 User 图标；昵称标签、浅色输入框和红色圆角主按钮依次排列。首次绑定引导主按钮为“保存并继续”，普通进入为“保存更新”。专属颜色集中在 tokens 的 profile-* 变量，主按钮复用品牌 primary，不加载字体或位图背景。

资料背景使用 1440 × 4480 SVG 设计画布，比初版增加 40% 高度；固定种子 20261117 保留原有上半部图案并延长至 80 个三角形，叠加红色至浅米色连续渐变和三处细线。自设计坐标 y=2000 起，背景连同三角形、装饰线逐渐淡出，到 y=4200 完全变白，末端保留纯白。尺寸是矢量坐标，不限制设备像素密度。页面壳使用渲染视口的 100vh，不用 getWindowInfo.windowHeight 的内联高度覆盖；后者仅用于导航几何校验。背景通过 CSS vw/vh 取宽高所需的较大倍率等比覆盖，顶部对齐、水平居中，超出窗口裁切；不拉伸、不重复平铺、不随正文长度增长。页面壳和窗口底色统一白色。常见及加长竖屏比例使用同一素材，平台显示须独立验收。

生成器为 `scripts/design/render-miniapp-profile-background.py`，只在开发时执行，小程序不运行 Python 或随机生成逻辑。使用 `python -B scripts/design/render-miniapp-profile-background.py --svg-out <新文件路径>` 输出 SVG，附加 `--preview-dir <输出目录>` 可用 Pillow 生成背景 PNG 与八种视口裁切预览，包含 390 × 1180 和 390 × 1400 加长视口；脚本拒绝覆盖已有输出。SVG 生成只需 Python 标准库，不引入小程序依赖。调整后核对生成结果再替换 `src/assets/account-background.svg`；图片尺寸变化时同步 `components/account-background.scss` 的缩放比例。个人资料与我的通过共享 AccountBackground 组件消费同一素材及覆盖规则。Pillow 预览使用同一几何与配色，仅说明静态构图，不代替微信 SVG 实际渲染验收。

普通进入在卡片底部并排显示“返回首页”“进入我的”，保存更新后留页；onboarding=1 次要按钮仅显示“暂时跳过”，保存昵称成功或跳过均返回进入统一登录页前的全局目标，导航失败可再次点击主按钮仅重试返回。顶部返回在引导模式恢复原目标，普通模式返回已有页面栈，无上页时进入我的，失败就近提示。头像选择后立即上传并更新，已有头像保留确认后立即移除能力，不再显示头像草稿或二次保存；头像成功不自动离页，保留昵称输入。结果未知、读取或上传失败时就近给出文字反馈与适用查询/帮助入口，不能显示成功或自动离开。正文随内容增长滚动，保留底部安全区，不绘制系统状态栏、胶囊或手势条。微信窄屏、键盘、原生组件及真机视觉验收未执行。

### 我的页面

`pages/account/index` 与个人资料共用 components/AccountFrame，统一包含 AccountBackground、透明自定义导航、useNavigationLayout 的窗口和胶囊测量，以及导航以下的独立 ScrollView。我的不显示返回按钮，个人资料把现有返回与引导恢复逻辑传给框架，保持处理中禁用和失败反馈。正文顶部为凸出的圆形头像、昵称、欢迎语和佣金钱包、消费钱包、我的积分三项摘要，未绑定手机号时展示“未登录”和三点占位，下方显示“登录后查看订单与资产”及“去登录”。头像、未登录文本和去登录按钮均调用统一 beginAuthentication，目标为我的页面。

AccountFrame 及背景样式只由 `styles/app.scss` 通过 Sass `@use` 加载一次；框架和背景 TSX 不导入样式，避免主包与分包因业务组件引用顺序不同而产生 CSS 抽取顺序冲突。继续使用默认顺序告警，不设置 ignoreOrder。由我的进入的业务页面统一背景与导航时复用此框架和同一 SVG，按页面传入标题及返回动作，保留原有权限、业务状态、滚动和底部安全区；当前接入范围为我的和个人资料，其他页面尚未迁移。

已绑定手机号才挂载本人资料、会员状态、钱包和积分 Query，复用既有会话隔离键并在页面重新显示时刷新。头像和昵称来自本人资料或当前真实会话；两类钱包分别显示可用人民币金额，积分显示可用积分，保留后端字符串精度。加载、查询失败和账户缺失明确区分，基础账户缺失提示重新登录或联系帮助，失败提供重试，不伪造零余额。头像无值时显示剪影，来源无效及加载失败给出反馈；长昵称省略，点击进入个人资料，长金额允许换行。

订单区依次为待付款、待发货、待收货、售后服务、全部订单；既有其他订单状态在全部订单筛选中继续可达，不用分页条目数伪造角标。服务区固定四列三行，依次为会员中心、推荐分享、我的积分、收货地址、钱包与流水、佣金记录、历史提现、继续结算、个人资料、账户安全、隐私说明、帮助支持。公共 NutUI 图标配浅色圆角底，图标前景和背景颜色由 account-* tokens 管理。私有交易与资金入口统一登录并恢复原目标，个人资料维持基础身份权限，账户安全、隐私及帮助保留原访问边界。我的页面底部仅保留品牌页脚，不显示退出登录按钮及资金能力未开放提示；退出登录继续通过账户安全页操作，各业务页保留适用的能力说明。

原生四项 TabBar 继续由微信渲染，不绘制状态栏、胶囊或手势条，不额外添加 TabBar 占位。正文为头像凸出部分预留空间，避免被 ScrollView 顶边裁切；异常提示和资产换行按内容增长滚动。小程序静态检查与微信视觉、真实登录及数据联调分别留证。

### 通用状态

| 状态 | 展示 | 可执行动作 |
| --- | --- | --- |
| 首次加载 | 稳定布局的骨架/加载提示，禁止闪现“空购物车” | 等待，必要时取消当前页面 |
| 查询失败 | “加载失败，请重试”，保留适用追踪标识入口 | 重试查询，不重放交易写入 |
| 未登录 | “登录后查看购物车/订单”，公开浏览保持可用 | 用户发起登录，完成后恢复上下文 |
| 写成功、后续查询失败 | “已加入，购物车刷新失败” | 刷新购物车，不能诱导再加一次 |
| 报价变化 | 展示最新金额与需要重新确认的原因 | 用户确认最新报价后再提交 |
| 下单/支付未知 | “结果确认中，请稍后查询” | 查询订单，保留相同业务意图 |
| 支付弹窗返回 | “正在确认付款结果” | 查询 Backend，不显示已支付承诺 |
| 退款审核通过 | “审核通过，退款处理中” | 查询渠道资金结果 |
| 停用/撤销 | 明确会话失效与适用说明，清理私有内容 | 重新登录或联系运营 |

任何状态不能只用颜色、动画或短 Toast 表示。资金结果未确认时禁止绿色成功页、到账金额变化和重复支付按钮。失败反馈只出现必要信息，不展示后端堆栈、Token、OpenID 或完整收款资料。

账户设置沿用现有 tokens 与基础组件。会话展示当前/有效/过期/撤销及脱敏网络段，不把会话称为可信设备；撤销确认显示目标数量与后果，原集合未知结果保留查询和主动恢复入口。注销页明确自助注销关闭，公开说明可直接阅读，本人核对需要登录；查询失败、未开通与未发现待处理事项分别展示，全部未发现也不显示可注销。设置、会话、注销前置已有源码，微信尺寸、长文本及交互验收未执行。

## 7. 安全区、响应与动效

- 底部动作区使用平台安全区尺寸，正文预留实际底栏加安全区高度；使用原生 TabBar 的页面不重复补一份 TabBar 占位。
- SKU 弹层最大高度为可用视口的 80%，中部内容滚动；顶部关闭和底部确认保持可达，键盘与安全区不遮挡金额。
- 在 320、375、414 逻辑像素宽度以及适用的更宽微信窗口核对长标题、两列卡片和横向溢出；文字增大不能造成按钮不可达。
- 重要金额不截断，长商品名称可折行或省略并通过详情查看；手机号和地址按隐私策略展示。
- 原生控件、相机/图片预览和弹层层级按微信实际渲染核对，不用任意超大 z-index 代替平台适配。
- 仅保留必要的点击、加载和弹层动效，常规过渡 160 至 240 ms；不使用自动轮播、收益跳动、长时间闪烁或大幅位移动画。

## 8. 设计交付与视觉验收

后续页面设计与实现先套用本文 tokens，再落组件。页面原型覆盖首页、分类、商品详情/SKU、购物车、结算、订单、售后和我的；每页至少包含正常、加载、空态、失败及适用的未登录/未知结果状态。

在明确授权的微信工具与 iOS/Android 真机验收中检查：点击区、字体和颜色对比、长文本、图片失败、键盘、安全区、横向溢出、弹层滚动、重复提交保护、前后台恢复、支付返回和账户隔离。普通文字对比目标至少 4.5:1，大字号至少 3:1；状态还须有文字或图标辅助。仅静态规范或截图不算交互与资金验收。

页面设计资产统一维护在 `docs/design/miniapp/`，已有核心与全套状态图。当前公开浏览按确认的风格直接落地可编辑 Taro 页面，交互源文件位于 apps/miniapp/src；独立 HTML/CSS 业务原型未生成，后续按需作为离线设计资料制作，不启动 Web 服务、不进入冻结的 apps/web，也不代替微信端验收。

当前保留已确认风格的 V1 核心页面图，并已按 PRD 与后端现有能力扩展 V2 全页面和关键状态；具体范围以设计目录为准。tokens 与公共组件已有源码，公开浏览、基础交易、履约售后评价与帮助已沿用实现；微信工具、窄屏/键盘/安全区视觉及真机验收未执行。独立 HTML/CSS 业务原型未生成。后续品牌调整集中修改 tokens 与适用设计说明，不同时维护另一套页面配色。
