# 商城后端领域与实施设计

## 1. 定位

本文是四阶段后端建设的目标设计与 M1 实施说明，不能作为功能已完成的证据。业务验收唯一来源为[产品需求基线](../PROJECT_REQUIREMENTS.md)，执行状态见[四阶段计划](../../plans/2026-09-17_商城后端四阶段建设计划.md)。

## 2. 所有权与依赖

| 领域 | 拥有数据 | 对外职责 |
| --- | --- | --- |
| products | 分类、商品、稳定 SKU、商品图片关联 | 商品管理、可售状态与商品快照 |
| inventory | SKU 库存账户、库存变动记录 | 初始化、调整、后续占用确认释放 |
| addresses | 用户收货地址 | 本人管理、默认地址和快照 |
| shipping | 运费模板、地区规则 | 模板管理、校验与运费报价 |
| cart | 购物车条目 | 购物意图，不保存权威成交金额 |
| orders | 订单、订单明细、状态历史 | 状态转换、快照与交易身份 |
| payment | 支付尝试、退款执行、通知与核对记录 | 外部资金事实、幂等与确认 |
| reviews | 已购评价 | 评价资格和公开展示 |
| distribution | 推荐关系、规则版本、佣金明细 | 最多两级归属、佣金生命周期 |
| wallet | 账户、业务冻结、资金流水、提现 | 资金权利与可追溯变动 |

后续领域名称及接口在进入里程碑前细化。Model 沿用项目 db/models 路径，路径集中不授予跨领域写权限。各领域公开入口输出 DTO 或提供明确命令；跨领域用例在 app/services 中装配，禁止公开接口泄露可被调用方修改的 ORM 对象。

## 3. M1 数据与接口设计

### 商品

- 分类为父子树，最多三级；结构写入使用数据库事务内固定锁，防止并发改父级构造环。
- SPU 保存名称、说明、类型、分类、运费模板及草稿/上架/下架状态。
- 每个 SPU 拥有稳定 SKU；无规格商品也使用默认 SKU。编码唯一，规格使用 JSONB，价格使用 Numeric，重量单位为克。
- 更新 SKU 以 ID 定位并校验商品归属，不全量删除重建。SKU 停用表达不可售，历史标识保留。
- 商品图片关联统一资产 ID，绑定时锁定并验证图片资产，资产删除时检查引用。仍被引用时明确拒绝删除。
- 商品公开 DTO 与管理 DTO 分开，不输出成本、内部备注或权限信息。

### 库存

- 库存账户以 SKU 唯一，available 与 reserved 均非负，revision 用于拒绝陈旧写入。
- 人工调整只修改 available；每次调整保存 request_id、SKU、变动数量、前后数量、原因和操作者。
- 同一请求号只能代表同一内容；重复相同请求返回已完成结果，不重复调整。相同请求号不同内容返回冲突。
- 下单占用、支付确认和取消释放进入 M2，M1 不开放伪造订单状态的库存端点。
- SKU 创建及库存初始化通过同一应用事务完成；商品编辑不直接更新库存表。

### 地址

- 地址写入以用户为粒度串行，写入前核对当前用户有效状态。
- 地址保存收件人、手机、行政区编码与名称、详细地址和默认标记。
- 数据库使用条件唯一索引限制每用户至多一个默认地址；删除默认地址后按创建时间和 ID 选择替补。
- 本阶段复用现有用户认证依赖，不宣称小程序登录已完成。未来 Public Client Profile 适配相同用户 ID。

### 运费

- 模板包含名称、计费方式、状态、版本、包邮门槛和排除省份。
- 地区规则包含省份列表、首单位/首费、续单位/续费。默认规则唯一，显式省份不能重复归属。
- 按件计费使用整数件数，按重计费使用整数克；金额保留两位，单位进位使用 Decimal 的 ROUND_CEILING。
- M1 拒绝停用模板的新绑定、上架和报价，模板编辑按行锁与 revision 校验；M1 不开放模板删除接口，数据库引用采用 RESTRICT。
- 运费超过 Numeric(15,2) 上限时明确拒绝。后续结算须重新校验模板状态与规则版本；未来若开放删除，须补齐锁定和引用检查。

### 接口形态

管理 API 使用 /api/v1/admin 下的 products、inventory、shipping 等领域路径；消费者 API 按 products、addresses 等领域组织。具体机器契约只由后端导出至根 openapi.json，不维护另一份字段契约。列表有界分页，写操作使用明确请求 Schema，版本冲突不静默覆盖。

## 4. 应用事务与安全

管理写操作经过管理员会话、精确 PermissionCode、CSRF、事务内权威校验和 AuditCoordinator。外层编排拥有事务，领域内部命令与 Repository 不提交；Repository 返回权威数据，应用服务决定授权。M1 未提供批量管理接口，后续新增时必须限制 1 至 100 个唯一 ID，固定排序锁定并全有或全无。

商品、库存、地址和运费按领域定义稳定错误码，统一 AppException 和 ResponseModel。未知错误明确传播，数据库约束冲突只在能识别业务约束时映射为业务冲突。

## 5. M2 至 M4 的衔接边界

1. 商品和地址提供快照 DTO；订单拥有快照，不保留对可变商品资料的强依赖。
2. 成交价格只由服务端计价；未来会员折扣必须同时进入预览和最终下单，快照保存生效规则版本。
3. 库存占用以订单业务标识幂等；任务必须有持久扫描依据、领取和重试边界，不能只依赖进程内计时器。
4. 外部资金调用采用持久意图、事务外调用、结果确认与短事务落库。超时保留结果未知。
5. 部分退款以退款单独立跟踪金额与数量，支付执行必须收到申请金额；订单、库存和佣金根据确认结果编排。
6. 两级分佣保存受益人与规则快照，退款追佣覆盖冻结、已结算和已提现场景；资金政策明确后再实现。
7. 双轨账户不采用一个共享冻结余额混合表达所有权利；具体账户和转移规则以获确认的需求为准。
8. 微信身份接入复用用户基础与审计，独立扩展适合小程序的会话 Profile，不复制参考仓库整套认证。

## 6. M2 交易实际边界

交易阶段新增购物车、结算预览、订单、订单明细、状态事件和库存占用数据。购物车只保存用户意图，写入时校验当前 SKU 可售和可用库存，不占用库存也不保存成交价格。

预览和创建订单共用服务端计价：同一 SKU 先合并数量，实物和虚拟商品拒绝混单；实物订单必须使用本人地址，虚拟订单没有地址快照。同一运费模板聚合件数或重量与组内商品金额后计费，不同模板运费相加。报价指纹覆盖商品、价格、规格、地址及运费规则快照；下单在事务内重新计算，指纹不一致明确拒绝。

订单按用户和请求号幂等，保存规范请求摘要。创建时依次串行同一用户请求、商品目录、稳定 SKU、运费模板和库存账户，模板与库存均按固定 ID 顺序锁定并刷新读取，订单、明细、事件和占用在同一事务写入。可用库存转为占用库存，取消或超时将占用释放回可用；可信支付确认的内部入口将占用扣减为已确认。客户端和管理员没有手工标记支付的 API。

订单状态当前只有 pending_payment、paid 和 cancelled。待付款时限固定 30 分钟，独立的 `scripts.expire_pending_orders` 命令默认 dry-run；显式 `--apply` 且精确确认数据库名后，按持久化到期时间使用 `SKIP LOCKED` 领取并关闭订单。命令未由应用启动或定时任务自动调用。

### 订单快照和后续边界

订单明细固化商品名称、SKU 编码、规格、数量、成交单价、重量和商品版本；订单固化地址、运费分组、规则版本与金额。内部支付确认在渠道确认时间达到订单到期点后明确拒绝。渠道适配、验签参数、关单和结果未知后的恢复策略由 M3 支付领域继续实现。

## 7. M3 支付与售后实际边界

M3 新增支付意图与状态事件、履约与状态事件、退款申请与明细状态事件、公开评价和渠道账单对账记录。支付意图按用户请求号幂等，保存商户参考号、金额、币种和渠道状态。微信和支付宝尚未配置时，服务明确保存 `unavailable` 状态，不提供伪造支付成功 API。

可信支付确认仅为内部应用入口，调用方须在渠道验签、商户与应用、订单、金额、币种核对后传入唯一渠道流水和已脱敏载荷摘要。确认付款、确认库存占用、创建履约单和支付事件在同一短事务内完成。当前没有公开回调路由、真实渠道适配器、验签密钥或外部资金调用。

实物履约从待发货进入已发货，再由用户确认或发货满七日的持久化扫描进入已交付；虚拟订单由管理员登记交付引用后完成。自动确认命令 `scripts.auto_confirm_fulfillments` 默认 dry-run，并要求精确数据库确认与显式 `--apply`。

退款仅支持已交付订单的订单明细商品金额和数量，不退运费、不自动入库。申请、审核通过或驳回与渠道退款确认均有独立状态和事件；渠道退款执行及确认仍待真实适配器实现。评价限制为本人已交付订单明细，一条明细仅一条公开评价。对账导入只记录渠道账单与本地支付事实匹配或差异，不改变订单、支付或退款状态。

## 8. M1 实际边界

已提供分类查询与创建更新、商品管理与公开查询、SKU 新增及原位修改、上下架、库存查询调整与流水、本人地址管理、运费模板创建更新查询与试算。商品列表批量读取变体和图片，避免逐商品加载。

分类、商品、SKU、模板当前通过启停或上下架管理生命周期，未提供复制、物理删除、批量操作和管理后台页面。订单商品快照、库存占用释放、支付与分销仍属后续阶段。地址具备本人快照读取入口，尚未接入订单。新增八张表只交付迁移文件，运行环境须经独立授权执行迁移和权限同步后才能使用新接口。

## 9. 迁移、验证和交付

每阶段新增不可变 Alembic revision；不执行共享数据库变更或导入参考数据。权限目录通过独立受控命令同步，应用启动不自动改权限表。

默认执行后端轻量门禁、契约生成及受影响治理检查。测试源码应覆盖领域不变量、拒绝、回滚、幂等和状态冲突；实际 pytest、真实 PostgreSQL 并发及迁移、渠道联调仅在当前任务明确点名授权后运行。未运行的验证不得记为通过。
