# 核心页面流程与状态

本文件描述设计稿的页面衔接与后续原型覆盖范围；功能、价格和资金政策以[小程序 PRD](../../MINIAPP_PRD.md)为准，状态文案以[UI 规范](../../architecture/miniapp-ui-standard.md)为准。

## 第一批页面衔接

1. 首页公开展示服务端返回的分类与商品，点击商品进入详情。设计稿中的分类、图片和价格仅为示例。
2. 详情展示主图、参考价格与商品信息。向下滚动继续展示受限 HTML 说明、独立详情图集和评价，不将设计首屏视为完整详情页。
3. 点击规格行打开选择弹层。点击加入购物车或立即购买时带入对应动作意图；当前图稿只展示加购意图。
4. 在弹层选择服务端允许的颜色、尺码和数量。不可售选项不可选择并展示原因，组合与数量不得由页面猜测。
5. 确认加购时处理登录与服务端校验。成功写入后刷新同一购物车查询，后续查询失败须明确提示，不能引导重复写入。
6. 立即购买意图转入后续结算页，由服务端重新报价；不会在前端直接决定应付金额或生成支付成功。

公开浏览不强制登录。登录取消保留浏览上下文；服务端拒绝、规格失效和数量冲突须说明原因，不自动替换规格。弹层关闭、遮罩点击、键盘、滚动与返回行为在后续原型和微信实现中核对，静态图无法验证。

## V2 全链路设计

全套图片见[设计目录](catalog-v2.md)，每个页面的当前 API 与目标边界见[接口映射](api-coverage.md)。用户已确认 V1 风格，本轮扩展全套图的内容与流程尚待评审。

1. 浏览：首页 → 分类/下级分类 → 商品详情 → 规格选择/图集/评价；分类过滤是待补齐的消费端能力，不能用本地当前页过滤替代。
2. 身份：私有动作 → 主动微信登录 → 协议确认 → 恢复原意图 → 用户再次确认操作；取消后继续公开浏览。微信身份、Bearer 与无密码账户已有源码，默认登录关闭，实际平台验收未执行；分享意图也须当前账户主动确认。
3. 购买：购物车 → 选择有效条目 → 实物地址或虚拟交付说明 → 服务端报价 → 用户确认 → 提交中 → 已知订单或结果确认中；零应付走内部成交。地址缺失、配送拒绝和混合类型都阻止提交。
4. 订单：本人列表目标 → 单笔详情 → 支付状态与独立履约 → 发货信息/虚拟交付 → 收货确认 → 评价。待付款取消、支付时限、晚到收款与结果未知各有独立图稿，真实渠道仍需接入。
5. 售后：已成交且未发货/未交付 → 整单退款原因 → 按接单事实自动或人工审核 → 审核通过 → 资金确认 → 已完成。已发货/已交付不能新增本期正常退款，拒绝与未知结果保留查询和帮助。
6. 个人与地址：个人中心 → 资料/头像 → 设置/设备/退出/注销；地址管理 → 新增/编辑 → 地区选择 → 默认地址 → 结算选择。删除与版本冲突显式确认；隐私与服务协议只为草案结构。
7. 会员与资金：主动开通档案 → 确认首次推荐绑定 → 分享目标 → 佣金冻结/结算/追回 → 两类钱包 → 提现记录及处理状态。本人推荐、原码匹配恢复、固定分享页、积分与钱包流水已有源码；落地参数与登录不自动绑定。真实提现开放前禁用申请，不提供充值、互转、积分兑换或抵扣；平台与动态验收未完成。

静态图展示弹层打开、按钮禁用、规格选中、表单校验、提交中和结果反馈；动画、点击、键盘、滚动和真实请求仍需后续业务原型与微信实现。图库的页面链接只是图片导航，不实现这些业务动作。

## 状态覆盖登记

| 页面/组件 | V1 覆盖 | V2 图片覆盖与后续边界 |
| --- | --- | --- |
| 首页/分类 | 有商品列表 | 正常、加载、空态、失败与分类目标；分页和长列表交互待原型 |
| 详情 | 可浏览首屏 | 说明/图集、虚拟商品、图片失败、下架、评价、加载与失败；长标题适配待工程 |
| SKU/购物车 | 已选规格、不可售、数量 1 | 加购/购买、库存不足、失效条目、删除、版本冲突、成功后刷新失败；真实选择和数量输入待原型 |
| 身份/资料 | 无私有内容 | 登录、取消、过期恢复、停用、退出、设备与凭据适用范围；账户切换隔离待工程 |
| 交易/售后 | 未画 | 报价变化、提交中/未知、支付与退款进度、审核/到账分离、收货确认、评价资格 |
| 地址/会员/钱包 | 未画 | 默认与删除、表单校验、地区/版本/数量上限；推荐拒绝、欠款、佣金与提现关键状态 |

图片完整清单以 V2 目录为准，未列出的交互细节不视为已交付。静态图不构成完整应用验收，设计说明不新增 API 契约或认证方案。
