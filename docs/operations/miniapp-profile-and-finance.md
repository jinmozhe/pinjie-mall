# 小程序个人资料、会员与资金查询接入

## 1. 当前范围与前置条件

个人中心已接入六个页面：个人资料、会员中心、双轨钱包、指定钱包流水、佣金记录及历史提现记录。源码和生成契约已实现，默认微信登录关闭。首次联调需先完成[独立身份手册](miniapp-identity-and-content.md)的 AppID、服务端秘密、身份迁移与登录配置；本阶段不新增迁移或依赖。

开发继续在仓库根目录运行 `pnpm --filter @pinjie/miniapp dev:weapp`，微信开发者工具加载 watch 输出。修改源码由 watch 增量编译，不需要每次手工运行完整构建。配置、依赖或编译器变化按[本地开发手册](local-dev-environment.md)重启 watch。本阶段未执行微信编译或平台验收。

## 2. 本人资料与头像

| 操作 | MiniappBearer 接口 | 约束 |
| --- | --- | --- |
| 本人资料 | `GET /api/v1/miniapp/me` | 仅返回本人公开标识、昵称、头像 |
| 保存昵称 | `PATCH /api/v1/miniapp/me` | display_name 去除首尾空白后 1 至 100 字，不允许 email 等额外字段 |
| 上传头像 | `POST /api/v1/miniapp/me/avatar-assets` | multipart 的 file，固定 avatar 场景，仅输出资产 ID 和 URL |
| 绑定或移除头像 | `PUT /api/v1/miniapp/me/avatar` | 必须显式提交 asset_id；null 移除，空对象拒绝；仅允许本人 avatar 资产 |

用户主动选图时才调用相册或相机。客户端限制单图不超过 2 MB，服务端复用既有 JPEG/PNG/WebP 文件头、扩展名、体积、存储与本人资产校验。上传成功只代表资产创建，用户点击保存后才绑定头像。头像使用既有资源来源准入，未准入地址与图片加载失败均给出反馈。

Taro.uploadFile 的响应 data 是字符串，上传传输层独立解析统一响应信封；不设置 JSON Content-Type，不把凭据写入 URL、日志或持久存储。退出、账户切换或失效会取消原生上传任务，旧响应不能回填新会话。失败结果未知时不自动重传。

资料写入失败先查询当前资料并由用户核对。查询显示当前事实，在途请求仍可能随后完成；后续修改由用户主动发起，不自动重放。停用账户在事务内重新校验并拒绝修改。

## 3. 会员与双轨钱包

| 操作 | MiniappBearer 接口 | 展示边界 |
| --- | --- | --- |
| 会员查询/主动开通 | `GET/POST /api/v1/miniapp/membership` | not_opened、no_level、active、inactive；开通复用既有幂等服务 |
| 双钱包 | `GET /api/v1/miniapp/wallets` | commission 与 consumption 的可用、冻结、欠款、版本和更新时间 |
| 钱包流水 | `GET /api/v1/miniapp/wallets/{wallet_type}/ledgers` | 本人指定轨道，展示三类余额变化、历史余额快照和版本 |
| 佣金记录 | `GET /api/v1/miniapp/commissions` | 本人冻结/结算/追回事实、金额与时间，无全量收益统计 |
| 历史提现 | `GET /api/v1/miniapp/withdrawals` | 本人审核状态与资金确认事实分别展示，不提供申请方法 |

列表使用 page、page_size，默认每页 10 条，最多 100 条，按记录 ID 倒序；不提供状态筛选。所有资金查询先校验账户有效，SQL 按本人钱包或本人受益人过滤。缺少钱包返回未开通错误，页面不伪造零余额。

开通档案不保证等级或收益，不绑定推荐人。会员查询只显示是否已有推荐关系与绑定时间，不输出推荐人标识或邀请码。等级价格权益由服务端报价确定，停用等级不应用价格权益。开通结果未知时先查询，不自动重试。

佣金钱包接收已结算佣金，按服务端资格提现，不能购物；消费钱包不能提现。两轨禁止互转，充值及消费钱包抵扣未开放。新入账与提现释放可能优先清偿追回欠款。冻结佣金记录与钱包中的提现冻结分别展示，不能合并成一个余额。金额直接展示服务端十进制值，不在客户端重新结算。

## 4. 资金确认与安全展示

审核通过不代表到账。历史提现仅在 succeeded 且有 confirmed_at 时展示确认事实；manual 渠道显示运营人工确认，其他已确认渠道显示服务端渠道确认。requested、approved、rejected、processing、unknown 及缺确认时间的 succeeded 都不声明资金已确认。真实自动打款未接通，新提现申请继续关闭。

消费者投影不输出买家/受益人身份、运营审核人员、完整佣金规则快照、订单明细关联、幂等键、收款目标、渠道引用或审核自由文本。流水余额快照只输出三类余额。私有 Query 按会话代次、轨道与页码隔离，页面返回时刷新，读取失败不继续呈现旧资金成功状态。帮助入口复用[履约售后手册](miniapp-fulfillment-and-aftersales.md)的公开支持配置。

## 5. 验证与后续验收

本阶段运行 Backend、Miniapp、Admin 轻量检查、契约导出和生成漂移核对及文档治理。新增回归测试源码覆盖输入、等级一致性、敏感投影、资金确认、私有身份拒绝、原生上传取消、会话旧响应及隔离 PostgreSQL 钱包分页与头像归属。

pytest、Vitest、微信编译/工具/真机、数据库动态验证与资金渠道未执行。后续专项须核验正式隐私声明、图片选择权限、API 与 uploadFile 合法域名、HTTPS、存储 URL 准入、本人隔离和未知结果恢复。推荐分享与积分查询已有后续源码，见[推荐积分手册](miniapp-referral-and-points.md)；有效邀请规则、注销与设备管理、真实支付及新提现仍需独立实施与验收。
