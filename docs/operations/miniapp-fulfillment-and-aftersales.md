# 小程序履约、售后、评价与帮助接入

## 当前边界

本人订单组合状态分页、履约详情与按版本确认收货、整单退款申请与原请求恢复、本人售后分页/详情、明细评价与已评价查询、公开帮助已有源码。复用既有后端写服务，不新增数据库模型、迁移、依赖或 Admin 权限。源码及静态门禁不代表平台、数据库、渠道或并发验收已完成。

微信登录默认关闭。公开商品与帮助可浏览，私有页面通过 AuthGate；启用条件沿用[身份接入手册](miniapp-identity-and-content.md#联调前置条件)。本地 watch 仍使用[本地开发手册](local-dev-environment.md#终端三小程序-watch-与微信开发者工具)中的 `pnpm --filter @pinjie/miniapp dev:weapp`，不启动 Web/H5 或 3000。

## 本人查询与操作

以下路径相对于 `/api/v1`，已并入原业务模块。私有操作拒绝 Cookie，响应 no-store，使用统一 ConsumerBearer，服务端检查本人归属；资格字段只作界面提示，写服务在事务内再次裁决。

| 接口 | 用途 |
| --- | --- |
| `GET /orders` | 服务端按订单主状态或履约事实筛选分页；相同筛选用于 total 与当前页 |
| `GET /orders/{order_id}` | 本人快照、成交时间、nullable 履约事实、确认收货/退款资格、本人明细评价 |
| `POST /orders/{order_id}/fulfillment/confirm-receipt` | 仅实物已发货，携带履约 revision；之后读取最新事实 |
| `GET /refunds/intent` | 取得服务端生成的新退款 request_id |
| `POST /orders/{order_id}/refunds` | 原 request_id 与 reason，服务端展开全部商品和原运费，无客户端金额/数量 |
| `GET /refunds` | 本人全量售后分页，可限定本人 order_id |
| `GET /refunds/{refund_id}` | 本人申请、审核、金额与安全资金投影 |
| `GET /refunds/by-request/{request_id}` | 显式 found/not_found，不把查询失败解释为未受理 |
| `POST /order-items/{order_item_id}/review` | 本人已交付明细，1 至 5 分、最多 1000 字，仅评价一次 |
| `GET /system/help` | 公开电话/邮箱配置，无联系人时返回明确 null |

订单主状态仍只有 pending_payment、paid、cancelled。display_status 为展示投影，待发货、待交付、待收货、已完成来自 paid 与履约事实；尚无履约时显示待确认，不能自行推定已完成。售后完成后的 paid 主状态保留，履约 cancelled 对应售后已完成。实物运单可复制，不提供实时轨迹；虚拟交付信息仅本人读取，界面仅在已交付时展示。

## 退款与未知结果恢复

1. 从订单详情进入整单申请，展示订单历史全量商品、原运费与总额；仅未发货/未交付可申请。未接单自动审核，已接单人工审核。
2. 首次发送前取得 request_id，将版本 1 的 userId、orderId、原请求号和原因保存在按用户及订单隔离的本机记录；存储失败不发送写入。不存 Token、密钥或完整收货地址。
3. 丢失响应、退出或登录失效后保留原内容。再次进入“退款资格与申请恢复”时查询原请求；只在服务端受理事实确认后清理记录。即使当前资格已改变，恢复入口仍可进入。
4. found 导向既有售后详情。not_found 仅表示当前未发现，可能仍有在途请求；用户可以继续查询或主动同键同内容重试。查询失败不发送退款写入；不新建请求号、不自动重放。
5. 售后详情分开展示申请 status、执行 execution_status 与资金 funds_status。审核通过、created、processing、unknown、abnormal 或 closed 均不能据此显示到账。
6. 正额退款只有 succeeded 且存在渠道确认时间才展示已确认资金事实，执行记录必须匹配本申请、订单、金额、币种与售后用途。零金额 completed 单独显示 no_funds，无资金退回。内部补偿完成时间与渠道确认时间分别保留。

申请与发货/虚拟交付竞争由既有事务锁与状态校验裁决。已经发货或已交付不开放本期正常售后；不支持部分数量或自算退款金额。退款执行异常继续查询并联系运营，客户端不能伪造渠道事实。

## 评价与帮助

评价页读取本人订单的 item_reviews，展示已评价事实或服务端资格。提交中禁用连点；提交结果未确认时锁定表单并提供查询与帮助，不自动重放写操作。商品公开评价在成功后失效刷新，每条明细仅能评价一次。

帮助页位于独立 service 分包，可从未登录页、个人中心、售后及评价页进入。常见问题可展开/收起；电话拨号和邮箱复制均反馈失败。没有聊天系统，也不编造主体、电话或邮箱。

在 Backend 的统一 Settings 配置 `SUPPORT_PHONE` 或 `SUPPORT_EMAIL`，填写经运营核实的公开信息。未准备好时保持变量未设置，不填空字符串或示例联系方式。电话只接受受限号码字符，邮箱需符合地址格式；配置改变按正常后端启动流程生效。此配置没有改动 Admin 站点设置，生产注入或部署需另行授权。
