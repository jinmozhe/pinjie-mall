# 商品详情图片启用与回填

## 1. 范围与前提

本手册适用于 `20260926_01`：新增商品详情关系和资产 width、height、frame_count。2026-09-26 本机开发库 `pinjie_mall_dev` 已在验证可读的迁移前备份后升级至该版本，2 条历史商品图片元数据已回填并复核无待处理项。隔离测试库迁移、重复升级、降级保护及其他动态验证仍未执行。不要在旧结构上启动新版本后端。

执行前取得目标环境操作授权，核对环境、数据库名称、备份、文件卷和可恢复版本。按[数据库备份恢复手册](database-backup-restore.md)保留数据库及不可变素材文件的一致性备份；不把凭据或连接串写入命令记录。

## 2. 启用顺序

1. 人工审查新增迁移、模型约束和恢复边界，确认调用商品更新的消费者清单。当前活动消费者为 Admin，Web 冻结，小程序未实施。
2. 在维护窗口停止相关写入，完成已授权备份；在 `apps/backend` 执行下列升级命令。数据库目标取自已核对的受控配置，不能只凭默认配置执行。
3. 执行同一节的显式目标回填检查，根据结果选择需要用于详情的历史图片进行回填；新上传图片自动获取可信元数据。
4. 协调切换 Backend 和 Admin，刷新旧编辑页面。更新请求新增必填 `detail_image_asset_ids`，旧请求返回 422，不能缺字段清空历史关联。
5. 验证两组图片顺序、保存 revision、资产引用删除保护及公开详情投影，观察 422、409、上传和回填失败。重型测试与数据库验证需单独授权后按项目入口执行。

已授权后的迁移命令：

```powershell
uv run alembic upgrade 20260926_01
```

精确契约例外及清理期限记录在[实施计划](../../plans/2026-09-26_商品详情图集与资产复用计划.md#78-已批准契约迁移与精确门禁例外)。例外仅处理已审查的静态诊断，不替代真实启用验收。

## 3. 历史资产检查与应用

所有命令在 `apps/backend` 执行。将示例名称替换为已核对数据库名称；测试环境继续必须使用隔离测试数据库。

```powershell
uv run python -m scripts.backfill_asset_image_metadata --confirm-database <数据库名称> --check --limit 100
uv run python -m scripts.backfill_asset_image_metadata --confirm-database <数据库名称> --apply --asset-id <资产UUID>
```

- 默认模式为只读检查。每批最多 100 个唯一资产；不指定 ID 时只选缺元数据的 product JPEG/PNG/WebP，按 UUID 有序取有界批次。
- `ready` 表示文件核验通过但尚未写入；check 有 ready 或任何失败状态退出 1，无待处理项或指定项已完成才退出 0。
- `updated` 为成功写入，`already_complete` 为已完成；apply 批次逐项独立提交，部分失败退出 1，不能把整批当作原子操作。
- `missing/file_missing` 表示记录或文件缺失；`unsupported/file_too_large` 表示场景、驱动或文件预算不适用；`invalid_image_or_hash` 表示解码、字节数或哈希不一致；`storage_busy` 表示完整解码队列等待超时，可在负载恢复后重试；`storage_failed/conflict` 需核对存储或并发状态。
- 失败记录不会被删除，也不伪造元数据。没有 ID 的默认批次可能重复选到未解决失败项；保存报告、解决原因，或按明确资产 ID 推进后续批次，禁止无条件循环重试。
- 解码在数据库写事务外完成，写前锁定资产并重新核验文件键、哈希、大小、类型、场景和存储驱动；完整解码每个存储实例单并发，排队超过 10 秒返回 `storage_busy`；受控删除与绑定共用资产锁。应用不重写图片原字节，人工修改磁盘文件属于存储完整性事故。
- 完成回填不代表素材满足详情预算。超过详情预算或动画素材仍可保留原资产，但不可绑定到详情；旧轮播不要求立即全量回填。

## 4. 日常运营

详情最多 20 张静态 JPEG/PNG/WebP，单张 2 MiB、整组 20 MiB、单边 4096、单张 800 万像素。图集只保存资产引用和顺序，说明继续是纯文本。图片按选择顺序排队，失败可重试或确认移除后保存；移除关联和取消商品编辑不会删除上传文件。

资产上传即公开，草稿或下架不会使素材私有。未绑定文件沿用现有资产管理清理，引用中的轮播、详情、品牌和头像均阻止物理删除。Admin 手机预览只模拟内容，不代表小程序性能及真机兼容结论。

## 5. 故障与恢复

数据库迁移后优先前向修复；停止相关写入、保存失败报告与受控日志，再核对素材及关联。不要因页面保存失败而删除已经上传的共享文件。

downgrade 在存在任何详情关联或图片元数据时明确拒绝有损删除。空扩展结构才允许经独立授权降级；已有数据时必须使用经验证且另行授权的数据库及文件一致性恢复方案。回滚 Backend 也要协调 Admin，避免新旧字段错配。生产恢复记录保存不可变版本或完整 40 位 Git SHA，禁止只记录分支名。
