# 数据库备份与恢复手册

## 1. 目标

本手册定义 PostgreSQL 备份、恢复、验证和演练边界。具体主机、数据库名、存储位置、凭据和命令参数属于本商城的受控运维配置，不写入仓库。

## 2. 基本原则

- PostgreSQL 是关系数据权威来源。
- 备份与生产数据库分离存储，至少保留一个独立故障域副本。
- 备份文件加密，访问遵循最小权限。
- 备份任务成功只证明文件产生，不能证明可恢复。
- 恢复演练在隔离环境执行，禁止覆盖开发、共享或生产数据库。
- 生产恢复、数据库降级和数据覆盖必须取得专项授权。

## 3. 商城部署必填参数

生产前必须记录：

| 参数 | 要求 |
| --- | --- |
| RPO | 最大可接受数据丢失时间 |
| RTO | 关键能力恢复的最长时间 |
| 备份类型 | 全量、增量或时间点恢复能力 |
| 频率 | 根据 RPO 推导，不凭经验随意设置 |
| 保留期 | 覆盖误操作发现窗口和合规要求 |
| 存储位置 | 与生产实例隔离，说明异地边界 |
| 加密 | 传输和静态加密方式及密钥所有者 |
| 负责人 | 备份、演练、故障恢复和审批负责人 |

## 4. 备份检查

每次备份任务至少核验：

1. 目标环境和数据库身份。
2. 开始时间、结束时间、退出状态和文件大小。
3. 备份文件校验和。
4. 加密和存储复制状态。
5. 备份与应用 Commit SHA、数据库 Alembic Revision 的关联。
6. 保留策略是否生效。

不得把数据库密码、连接串或备份加密密钥写入日志。

## 5. 恢复演练

1. 创建名称明确且隔离的恢复目标数据库。
2. 校验目标名称、主机和环境标识，任何不确定状态立即停止。
3. 从选定恢复点还原数据。
4. 验证 Alembic Revision、表数量、关键约束和应用要求的数据摘要。
5. 使用与恢复版本匹配的应用执行只读冒烟或受控测试。
6. 记录实际恢复时间、可恢复时间点、失败步骤和人工操作。
7. 演练结束后只把恢复数据库列为清理候选，按授权流程清理。

验证不能只执行 `SELECT 1`。本商城必须定义不泄露敏感数据的关键行数、约束状态、引用完整性和业务摘要检查。

### 5.1 本地演练入口

`apps/backend/scripts/verify_local_database_recovery.py` 从 Backend Settings 读取 `TEST_DATABASE_URL`，只接受本机 PostgreSQL 和以 `_test` 结尾的数据库。测试角色必须仅在本地具有创建演练数据库的权限。

在 `apps/backend` 目录执行：

```powershell
uv run python -m scripts.verify_local_database_recovery `
  --migration-database pinjie_migration_test `
  --restore-database pinjie_restore_test `
  --confirm-source-database pinjie_fullstack_test `
  --confirm-migration-database pinjie_migration_test `
  --confirm-restore-database pinjie_restore_test
```

脚本按顺序验证：

1. 源测试库升级、重复升级和 `alembic check`。
2. 新建空迁移库并执行升级、重复升级和 `alembic check`。
3. 调用 `scripts/operations/test-postgres-backup-restore.ps1` 完成 custom format 备份和恢复。
4. 比对 Alembic revision、public 表清单、逐表行数、约束数量和未验证约束。
5. 默认删除自己创建的迁移库、恢复库和临时 dump。

源库、迁移库和恢复库必须互不相同，三个确认值必须逐字匹配。目标恢复库已经存在时脚本拒绝覆盖。脚本不会输出密码，凭据只通过子进程环境传递。

## 6. 生产恢复

生产恢复前必须确认：

- 事故范围和数据继续变化的风险。
- 是否需要停止写入或切换只读状态。
- 选定恢复点与预计数据丢失窗口。
- 当前应用版本和目标数据库 Revision 的兼容性。
- 原数据库保全方式和回退路径。
- 最终授权人、执行人和观察人。

生产恢复后必须核对实际 RTO、RPO、关键数据摘要、应用错误率和审计记录。结果与目标不符时进入事故复盘，不能只记录“恢复完成”。

## 7. 迁移保护

- Schema 变化通过 Alembic 演进，禁止手工修改共享数据库。
- 发布前验证空库升级、现有结构升级和重复升级。
- 数据迁移在执行前估算锁表、耗时、空间和回滚影响。
- 不可逆迁移必须先产生并验证可用备份。
- Expand、Migrate、Contract 窗口按 [ADR 0007](../adr/0007-受控迁移兼容策略决策.md) 管理。

### 7.1 共享 PostgreSQL 实例

- 每个项目使用独立数据库、登录角色和强密码，应用禁止使用实例管理员或其他项目角色。
- 备份与恢复命令必须显式指定目标数据库，禁止使用未审查的实例级覆盖恢复影响其他项目。
- Custom Format 备份迁移到新角色时使用 `--no-owner --no-acl`，恢复时显式指定目标项目角色，并核对表、序列、函数和 Schema 所有权。
- 恢复前确认目标数据库为空或已取得覆盖恢复专项授权；已有目标默认拒绝覆盖。
- 共享实例仍需保留实例级灾难恢复备份，项目级备份不能覆盖角色、实例配置和其他数据库恢复需求。
- 迁移观察期内保留源数据库和备份，删除源容器、数据卷、数据库或角色需要独立授权。

## 8. 1Panel 边界

1Panel 可以调度共享 PostgreSQL 备份、保存运行日志和提供恢复入口，但项目负责人仍需验证备份实际可恢复。面板显示成功不能替代隔离恢复演练、数据校验和完整记录。共享 Redis 的持久化数据和配置必须进入基础设施备份范围；启用独立 ACL 文件时同时备份 ACL 文件。Redis 不得成为核心业务数据的唯一权威来源。
