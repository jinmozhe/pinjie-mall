# Admin 电商分阶段建设计划

## 1. 当前状态和结果

- 状态：实施中
- 结果：不适用
- 阶段：A0 至 A4 本地实现、契约同步与应用验证完成；临时资源清理及最终文本门禁受工具策略阻塞。

## 2. 关联需求

关联 `BASE-ADMIN-001`、`BASE-ADMIN-002`、`BASE-ADMIN-003`、`BASE-API-001`、`BASE-API-002`、`BASE-DB-001`、`BASE-QUAL-001`，商品阶段关联 `BASE-COM-001` 至 `BASE-COM-004`、`BASE-COM-006`，订单阶段关联 `BASE-COM-103`、`BASE-COM-105`、`BASE-COM-203`，售后阶段关联 `BASE-COM-202`、`BASE-COM-204`、`BASE-COM-205`，会员财务阶段关联 `BASE-COM-301` 至 `BASE-COM-305`。

## 3. 背景

后端 M1 至 M4 已有本地实现，Admin 只有通用管理页面。电商路由、Access 与请求封装尚未接入；部分运营查询、筛选和批量接口缺失。运行库已到 `20260917_05`，权限目录尚未同步；测试库可连接但为空，隔离测试 Redis 可连接。

## 4. 目标

按五个阶段交付可操作、具备权限与错误反馈的电商后台，补齐对应后端接口及契约。各阶段共享本计划、生成链和验证证据，连续实施不重复请求实现授权。

## 5. 非目标

不开发小程序或冻结 Web，不接入真实支付、退款、提现及物流渠道，不改变会员价格与佣金政策，不提供伪造资金成功操作。不执行 Git 提交推送、发布部署。Admin build、Vitest、Playwright 未获点名授权，按策略不运行。

## 6. 现状分析

商品分类、商品/SKU、按 SKU 库存、运费模板已有单条管理接口。商品、订单、退款列表只有分页。订单详情、发货、虚拟交付、退款审核、提现待审列表及审核已存在。会员、推荐、佣金、钱包主要为本人接口，支付与对账管理查询尚缺。电商普通列表需要合法批量能力，不允许前端循环单条写接口。

## 7. 方案设计

### A0 测试与权限基线

核对本机测试 PostgreSQL 与 Redis 隔离；仅向已确认的空测试库应用现有迁移，检查版本与模型漂移，运行 Backend pytest 并保留 90% 覆盖率门禁。失败按真实原因修复，不跳过测试或降低阈值。核对并同步本地运行库权限目录，不自行扩大普通角色权限。

### A1 商品运营

交付分类、运费模板、商品列表及编辑、稳定 SKU、商品图片选择、库存调整与流水。商品支持名称/SKU 搜索、分类、状态、类型筛选；增加分类和运费模板批量启停、商品批量上下架。库存首批在商品详情内按 SKU 操作，库存流水保持不可变。验收链为建分类、配运费、建商品/SKU、配图、调整库存、上下架。

### A2 订单履约

交付订单列表、快照详情、履约状态、实物发货与虚拟交付。查询支持订单标识、用户、状态与类型等有契约的条件；批量动作保持同事务、固定锁序、版本核对。订单历史不可通过页面任意改价或修改状态。

### A3 售后与支付查询

交付退款列表与审核、支付记录和对账记录查询及既有对账录入。区分审核通过、渠道执行、结果未知与最终成功；查询不能改变资金状态。按业务语义提供审核或受权限保护的选中记录导出，不增加无依据删除。

### A4 会员分销财务

交付会员档案、推荐关系、佣金、钱包与流水、提现查询审核。增加管理端只读查询及精确权限；普通业务列表提供受权限保护的选中导出，提现按既有状态机审核。不可变流水不提供人工修改或删除。保持固定等级、两级推荐和双轨资金权利，不提供余额修改、关系重绑或假打款。
