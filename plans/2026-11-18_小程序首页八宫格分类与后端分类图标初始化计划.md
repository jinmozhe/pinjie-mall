# 小程序首页八宫格分类与后端分类图标初始化计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；8 组彩色分类 SVG/PNG 生成与本机开发库 8 个一级分类幂等初始化完成，小程序首页 2×4 八宫格与跳转分类 Tab 页定位实现，适用轻量门禁通过，微信编译、Vitest、pytest 与真机动态验收未执行。

## 3. 背景

小程序当前首页和分类页共用同一横向胶囊分类条（`.category-strip`），尚缺少贴合真实业务结构的首批一级类目数据与彩色分类图标。用户希望首页顶部按 4 列 × 2 行的宫格效果展示 8 个一级类目（生鲜粮油、餐饮烘焙、家居日化、母婴亲子、宠物生活、名烟名酒、车主服务、生活服务），使用专属彩色 SVG 矢量设计并导出高清 PNG 绑定至后端分类资产，点击首页类目后跳转到“分类”Tab 页并自动定位到所选类目。

## 4. 目标

1. 为 8 个一级商品分类设计专属彩色 SVG 矢量图标（柔和彩色圆润底托 + 具象彩色主体图形），并通过同源脚本渲染为 `160×160` 高清透明 PNG。
2. 新建幂等后端种子数据与脚本 `apps/backend/scripts/seed_home_categories.py`，在本机开发库 `pinjie_mall_dev` 中写入 8 张图标资产（`assets` 表及本地存储文件）与 8 个一级分类（`product_categories` 表，固定 `sort_order` 1 至 8 并绑定 `icon_asset_id`），保留开发库既有分类和商品。
3. 改造小程序首页（`categoryMode = false`）顶部分类区为 4 列 × 2 行八宫格卡片样式（`96×96rpx` 图标 + `24rpx` 名称），点击后通过 `Taro.switchTab` 跳转到“分类”Tab 页并自动定位选中该类目。
4. 同步更新小程序 UI 规范、工程标准、Changelog、计划索引和项目索引，运行适用轻量门禁。

## 5. 非目标

- 不修改 PostgreSQL 数据库表结构（`product_categories` 已有 `name`、`parent_id`、`icon_asset_id`、`description`、`sort_order`、`is_active` 全部字段，无需新增 Alembic 迁移）。
- 不修改 OpenAPI 契约与 `packages/api-client`。
- 不新增前端轮播装修、搜索框、秒杀或优惠券入口。
- 不连接或操作 `_test` 测试库或生产库，不执行未获点名授权的 pytest、Vitest、production build、微信工具自动化或真机验收。

## 6. 现状分析

- Backend：`product_categories` 表和 `CategoryRead` 契约已支持 `icon_asset_id`、`icon_url`、`description`、`sort_order` 与 `is_active`。当前 `pinjie_mall_dev` 仅有 3 个分类（`虚拟`、`鞋子`、`服装`，`sort_order` 和 `icon_asset_id` 均为 `None`）。
- Miniapp：`apps/miniapp/src/features/catalog/CatalogPage.tsx` 已消费 `/product-categories` 返回的 `icon_url` 渲染分类图标；`pages/category/index.tsx` 通过 `<CatalogPage categoryMode />` 挂载分类 Tab 页，位于 `app.config.ts` 的 `tabBar.list` 中。

## 11. 风险与回滚

- 跨 Tab 定位状态若未在进入分类页时及时清理或未区分首次挂载与再次切回，可能导致后续手动点击“全部商品”被覆盖；通过一次性 `takePendingCategorySelection()` 在 `useState` 初始化及 `useDidShow` 中消费并立即清空来规避。
- 本机开发库若有既有分类占用 `sort_order` 1 至 8，脚本将其顺延至 `9+` 并保留原分类与商品，可随时在 Admin 中调整；图标资产写入遵循先 `stage` 后 `commit` 的原子替换并留存哈希。
