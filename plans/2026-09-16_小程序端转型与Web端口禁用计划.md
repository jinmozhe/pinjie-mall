# 小程序端转型与Web端口禁用计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；客户端形态确立为微信小程序端，彻底排除Web端需求，前阶段聚焦后端与管理端，完全禁止WEB端口，治理与轻量门禁全量通过

## 2. 关联需求

- `BASE-GEN-001`：母版全栈 Monorepo 应用与包边界定义
- `BASE-GEN-004`：目标能力、阶段导航、详细实现与交付历史分离
- `BASE-WEB-001`：Web 应用骨架与 C 端定位要求（在本项目中废弃）
- `BASE-OPS-001`：本地开发流程与运行端口定义

## 3. 背景

本项目定位为高可用标准电商与多级分销全栈商城平台。根据用户明确指示，本项目在应用层面上完全不需要 WEB 端，核心 C 端面向微信小程序，属于小程序商城项目。开发资源全面聚焦于小程序端配套的后端接口与管理后台。

## 4. 目标

1. 确立客户端定位：C 端交互形态明确为微信小程序端，应用层彻底排除 C 端 Web 应用（Next.js）。
2. 确立阶段推进边界：前阶段集中力量实现后端（Backend）业务领域及模型与管理后台（Admin），小程序端在前阶段先不开发，留待后续专项阶段实施。
3. 确立 Web 端停用原则：`apps/web` 目录进入全面冻结废弃状态，完全不需要 Web 端，禁止分配开发资源，禁止在本地或生产中运行 Web 端服务。
4. 全面同步规则、需求基线、项目索引、运维手册与开发脚本，形成工程治理防线。

## 5. 非目标

1. 不在当前阶段开发小程序端业务代码或引入小程序工程框架。
2. 不物理删除 `apps/web` 目录（防止破坏既有 CI 门禁脚本中对子应用的基线校验）。
3. 不变更后端既有已落地的核心数据模型或破坏已有接口契约。
4. 不在未授权情况下执行任何生产部署或发布动作。

## 6. 方案设计

1. 规则层（AGENTS.md）：在根规则及各端规则中注入小程序端定位、前阶段聚焦后端与管理端、完全禁止 WEB 端口的刚性约束。
2. 需求基线层（PRD）：在 `docs/PROJECT_REQUIREMENTS.md` 中调整目标用户与使用场景，将 `BASE-WEB-*` 标记为在本项目中废弃，追加小程序端目标规划（`BASE-MP-*`）并明确前阶段暂不开发。
3. 项目索引层：更新 `PROJECT_INDEX.md` 中当前阶段与项目身份描述，并将本计划登记为活动计划。
4. 编排与脚本层：
   - 调整根 `package.json` 中的 `dev` 脚本，防止 `turbo dev` 误启动 Web 端及占用 3000 端口。
   - 调整 `compose.prod.yml`，移除 Web 容器暴露的主机 3000 端口映射。
   - 更新 `apps/web/README.md` 与本地开发运维文档，明确标明 Web 端已停用及禁止 WEB 端口。

## 10. 风险与回滚

- 风险：若直接物理删除 `apps/web` 目录，会导致已有 CI 守卫与文档校验脚本报错。应对策略是保持目录结构，通过规则、脚本和编排将其完全冻结并禁止运行，彻底封禁端口。
- 回滚策略：若未来业务规划调整，可通过新的全栈计划重新评估 C 端形态并恢复相关配置。
