# 品牌 LOGO 上传与素材库选择闭环实施计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；品牌新建与编辑表单支持直接上传 LOGO 与素材库单选模态弹窗选择，移除手工输入 UUID 输入框，后端 BrandRead 联查回填 logo_url，列表呈现缩略图，全栈轻量与文档门禁全部通过；未执行重型验证已明确记录

## 2. 关联需求

- 关联需求：`BASE-ADMIN-004`（商品与运营支撑后台：分类、品牌、属性管理及统一主图/详情图与素材资产引用）、`BASE-API-001`（根 `openapi.json` 是唯一 OpenAPI 契约）、`BASE-API-002`（API Client 自动生成）、`BASE-GEN-004`（全栈计划管理）。

## 3. 背景

Admin 管理后台的“品牌管理”功能（`BrandsPage.tsx`）中，当前品牌 LOGO 字段通过原生单行文本框直接要求操作人员手工输入“文件资产 UUID（选填）”。这种形式存在严重的人机交互缺陷：

1. 操作人员无法直接在界面上上传本地图片作为品牌 LOGO；
2. 无法直接浏览和选取素材库中已有的图片资源；
3. 手动复制和输入 UUID 容易出错且无法直观预览当前选择的图片；
4. 列表与编辑抽屉缺少 LOGO 缩略图展示，品牌资料识别度低。

用户明确要求：可以直接上传 LOGO，也可以选择已经上传的素材，彻底移除人工手动输入 UUID 的形式。

## 4. 目标

1. **统一上传与素材选取交互**：在品牌新建与编辑表单中，提供开箱即用的品牌 LOGO 选择器，支持“直接上传本地图片”和“从素材库选择已有图片”，彻底移除手动输入 UUID 输入框。
2. **直观预览与生命周期操作**：支持所选 LOGO 的清晰缩略图预览（支持查看大图），支持“更换 LOGO”与“移除 LOGO”；移除 LOGO 时遵守管理端安全规范，通过 `StandardConfirmModal` 进行二次确认提示。
3. **素材选择模态窗（AssetSelectModal）**：提供轻量易用的素材选择器，支持场景过滤（商品/品牌类图片）、按文件名搜索、缩略图网格分页展示与单选确认。
4. **全链路数据打通（Backend + API Client）**：后端 `BrandRead` 返回 `logo_url`，在查询品牌详情及分页列表时联合查询资产公开访问地址，确保编辑已有品牌时能正常回显原 LOGO 图像，并在品牌列表表格中直观呈现 LOGO 列。
5. **契约与门禁闭环**：重新导出 OpenAPI 契约并生成 API Client，运行 Admin 与 Backend 适用轻量门禁，保证零 TypeScript 告警、零 Lint 告警。

## 5. 非目标

1. 不修改数据库表物理模型与迁移脚本（`brands.logo_asset_id` 既有外键字段满足需求）。
2. 不修改已冻结的 Web 端代码。
3. 不执行未经用户明确授权的 Admin production build、端到端 E2E 浏览器自动化或重型测试。

## 6. 现状分析

1. **后端状态**：
   - `Brand` 模型（`apps/backend/app/db/models/catalog.py`）中包含 `logo_asset_id: UUID | None`，已关联外键指向 `assets.id`。
   - `BrandRead`（`apps/backend/app/domains/products/catalog_schemas.py`）仅返回 `logo_asset_id`，未返回 `logo_url`，导致前端拿到品牌数据时无法直接渲染图片，列表也无法直接显示 LOGO。
   - `apps/backend/app/services/commerce.py` 的 `_product_dependencies` 强制校验了品牌关联资产的 `scene == "product"`、`uploader_type in {"admin", "system"}` 以及 MIME 为图片格式。因此品牌 LOGO 资产的上传和选择场景必须限定为 `"product"`。
2. **前端状态**：
   - `BrandsPage.tsx` 中的 `BrandEditor` 目前包含 `<Form.Item name="logo_asset_id" label="LOGO 资产标识"><Input maxLength={64} placeholder="文件资产 UUID（选填）" /></Form.Item>`。
   - 品牌列表 `ResourceTable` 的列中仅有“品牌名称、描述、状态、版本、操作”，缺少 LOGO 图片列。
   - 前端已具备 `adminApi.uploadAsset(file, "product")` 和 `adminApi.assets(...)` 资产接口，但缺乏一个通用的单张图片“上传+素材库选择”控件。

## 7. 方案设计

1. **后端契约与查询扩展**：
   - 在 `BrandRead` 中增加 `logo_url: str | None = Field(default=None, description="品牌 LOGO 图片公开访问地址")`。
   - 在 `CatalogRepository.brand` 和 `CatalogRepository.brand_page` 查询中，通过 `select(Brand, Asset.url).outerjoin(Asset, Brand.logo_asset_id == Asset.id)` 联合查询，将 `Asset.url` 回填至 `BrandRead.logo_url`。
   - 在 `CatalogService.save_brand` 中保存品牌后，回填 `logo_url`。
   - 运行 OpenAPI 导出与 `pnpm generate-api` 重新生成 API Client。
2. **Admin 组件设计**：
   - 新增通用的 `AssetSelectModal`（素材库选择弹窗）和 `BrandLogoPicker`（或整合进 `ImageUploader`）：
     - 支持上传：限制 `jpg, jpeg, png, webp` 格式，大小限制 2MB/10MB，上传调用 `adminApi.uploadAsset(file, "product")`，获得 `id` 和 `url`。
     - 支持素材库选择：打开 `AssetSelectModal`，搜索 `product` 场景的图片，缩略图网格单选，点击确定回填 `id` 和 `url`。
     - 状态管理：表单收集 `logo_asset_id`，UI 同时维护 `logoUrl` 供预览展示。
     - 移除确认：点击移除触发 `StandardConfirmModal` 二次确认弹窗，说明“移除后保存生效，原文件仍保留在素材库中”，确认后清空。
3. **品牌列表与编辑体验升级**：
   - `BrandEditor`：使用新设计的 LOGO 选择器替换 UUID 输入框，编辑已有品牌时根据 `target.logo_asset_id` 和 `target.logo_url` 自动回显预览图。
   - `BrandsPage` 列表：在“品牌名称”列前添加“LOGO”列，渲染 36x36 缩略图（带悬浮大图预览），无 LOGO 时显示占位图标。
