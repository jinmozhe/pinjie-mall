# 后端目标模型总核对与任务恢复验证计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；持久任务单轮 Worker、模型静态核对和适用轻量门禁已交付

## 2. 关联需求

- `BASE-COM-001` 至 `BASE-COM-004`：商品、库存、品牌和资产基础。
- `BASE-COM-201` 至 `BASE-COM-205`：支付、可信确认、履约、整单售后与对账。

## 3. 背景

阶段 1 至 5 已交付目标运行表、业务服务、迁移和生成契约。当前 18 张目标新增运行表均进入源码和 Alembic 图，但持久任务仅具备入队、租约、重试和人工关注状态，缺少受控的任务执行与恢复入口。实际数据库升级、PostgreSQL 事务并发、pytest 和外部渠道联调尚无当前任务的单项授权。

## 4. 目标

- 核对目标运行表、模型、迁移、OpenAPI、生成客户端和架构文档的可追溯一致性。
- 实现持久任务执行入口，使用短租约、任务类型白名单、幂等业务服务和有界重试恢复内部任务。
- 让无真实渠道的支付、退款和提现任务进入明确的不可用或待人工关注路径，不伪造渠道成功或静默丢弃。
- 记录本地静态验证和未执行的动态验证边界。

## 5. 非目标

- 不执行实际数据库升级、测试数据库迁移、pytest、PostgreSQL 并发验证或真实渠道联调。
- 不接入支付、退款、提现、微信身份或部署常驻 Worker。
- 不实现后续会员资格与积分五表，不改造 Admin 交易页面或小程序。

## 6. 现状分析

`durable_tasks` 已以业务键唯一、租约、失败阈值和 attention 状态保存可恢复意图。订单过期、自动确认收货和佣金结算已有内部服务入口；渠道相关任务没有可信适配器，不能由 Worker 假定成功。目标数据库字典现有 62 张源码表，其中 18 张为本轮路线新增运行表，另有 5 张会员资格和积分规划表不属于当前运行模型。

## 7. 方案设计

- 新增仅由命令行显式调用的持久任务执行器；每轮以独立短事务领取任务，再以独立短事务执行或更新任务结果，避免渠道等待期间持有业务锁。
- 内部任务处理器只调用已有幂等服务：订单过期、自动确认履约、佣金结算。每次处理严格校验任务载荷的 schema 与业务对象归属。
- 渠道任务统一通过明确的不可用处理器返回可重试错误；到达失败阈值转为 attention，保留错误代码和恢复证据，等待可信渠道适配器或人工处置。
- 对模型、迁移和文档做静态清单核对，补正能由源码直接证明的事实；公开接口变化才重新导出契约并生成客户端。

## 9. 实施顺序

1. 登记计划并核对目标表、迁移图、任务生产者和既有内部服务。
2. 实现受控持久任务执行与恢复入口，补齐错误传播和运行文档。
3. 静态核对模型、迁移、契约和文档事实，修正可证明的不一致。
4. 运行轻量门禁、契约生成和治理检查，记录动态验证的未执行状态。

## 11. 风险与回滚

- Worker 只能由显式命令启动，默认 dry-run 或受控单轮执行；不在应用启动时自动领取任务。
- 任务执行遇到未知渠道状态不写成功，不释放资金或库存；保留任务、错误和 attention 供恢复。
- 代码可通过停止 Worker 命令回退为既有仅入队模式；已有任务记录和迁移不删除。

## 15. 实施结果

已实现 `scripts.run_durable_tasks`，默认仅预览，经精确数据库确认和显式 `--apply` 后执行一轮有界任务。领取、内部业务处理和完成/重试分别使用短事务；完成与重试的更新条件以数据库 `clock_timestamp()` 复核当前租约。`expire_order`、`auto_confirm_fulfillment` 与 `commission_settlement` 由 Worker 调用已有幂等服务，发货事务已同步登记自动确认任务。支付、退款和提现任务因无可信渠道适配器返回明确的可重试不可用错误，达到阈值后转 attention，不伪造成功。

新增 `scripts.verify_target_model`，静态核对 SQLAlchemy 元数据中的 62 张当前表与 18 张目标新增运行表。人工复读 `20260922_01` 至 `20260922_05`，`alembic heads` 确认为唯一 head `20260922_05`。架构、数据库字典、Backend 运行说明、计划索引和项目索引已同步。

Backend Ruff、格式、Mypy、导入边界、编译、应用导入、模型清单和 Alembic head 通过；文档、文本、工作区、边界、依赖策略、生产配置、OpenAPI 例外、Markdown、治理守卫和 `git diff --check` 通过。已从最终应用重新导出根 OpenAPI 并生成 API Client。`lint:md` 已排除 Git 内部元数据及 `.gitignore` 排除的 `temp/` 历史参考资料，正式 Markdown 均受门禁覆盖。
