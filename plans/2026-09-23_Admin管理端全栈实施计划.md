## 3. 背景

后端已具备商品、会员价格与资格、积分、三级预算分佣、交易履约、整单售后、钱包和持久任务等内部能力。现有 Admin 保留认证、账号、权限、资产、设置和部分电商运营页面，但商品页仍显示迁移提示，新模型配置、查询和状态展示尚未全部适配。

本计划承接已讨论的整合菜单方案，以运营职责划分页面，以数据库字典核对覆盖，以实际源码与根 OpenAPI 判断可接入能力。字典 15 个分组用于资料组织，不直接映射为菜单，也不代表 15 个已实现领域。编制时字典和 ORM 表名均为 67 张且无差异，此结论不等于字段、运行结构和业务行为全部验证通过。

此前[Admin 电商分阶段建设计划](2026-09-18_Admin电商分阶段建设计划.md)已结束，保留其交付事实。本计划建设新模型下的完整管理入口，不替换或删除历史计划，也不重新实现已经完成的后端业务状态机。

## 4. 目标

1. 建立第 7.1 节登记的 8 个一级分组、29 个二级菜单，保留既有业务能力、认证、个人设置和权限行为。
2. 完成商品、会员、分销政策的新模型页面，以及交易、财务和系统页面的适配；移除已被实际功能替代的迁移占位提示。
3. 补齐退款执行、任务诊断、库存占用、限购和佣金追回查询，以及本计划新增普通列表必需的合法批量能力。
4. 以明确的主表、明细、事件和快照区分事实，避免把审核、渠道资金成功、内部补偿完成、人工对账处置混为一个状态。
5. 所有有效筛选在服务端执行，权限覆盖菜单、页内标签、按钮和后端端点，普通业务列表与不可变流水采用各自的操作规则。
6. 同步唯一契约、受影响测试源码和文档，通过授权范围内的轻量门禁；分别报告未执行的动态、视觉和真实渠道验证。

## 5. 非目标

- 本次编制任务不修改 Admin、Backend、数据库模型、生成客户端或运行配置，不启动应用和数据库服务。
- 不开发、启动、构建或测试冻结的 Web；禁止监听 3000。小程序工程和微信身份接入留待后续专项。
- 不增加营销、优惠券、拼团、秒杀、充值、积分兑换/到期/抵扣、消费钱包入金/支付或钱包互转能力。
- 不接入真实支付、退款、自动提现和物流轨迹渠道，不部署常驻 Worker，不实现告警投递或任务人工重试/取消/改状态。
- 不增加后台改绑推荐关系、直接修改余额/限购累计、伪造渠道成功、任意修改业务流水的入口。
- 不实施商品评价管理、图文评价、审核删评，也不增加用户购物车代改或全量地址簿管理。
- 不新增动态菜单表、通用 JSON 参数编辑器、第二套请求管道、第二份 DTO、替代 UI 库或无必要依赖升级。
- 不自动执行任何 Git 提交、推送、PR、发布、部署、权限数据写入、真实数据库迁移或生产动作。
- 本计划文字和后续普通实现授权均不自动授权 production build、Vitest、pytest、Playwright、浏览器自动化或测试数据库验证。

## 7. 方案设计

### 7.1 两级菜单与数据归属

菜单编号用于后续验收记录，不进入产品界面。分组数量为 8，二级页面数量为 29；详情、编辑、流水和标签不增加左侧菜单层级。涉及表表示查询或业务归属，页面只通过后端公开接口访问。

### 7.2 页内结构及不进入菜单的数据

| 数据或功能 | 落实位置 | 边界 |
| --- | --- | --- |
| 用户回收站、会话 | 用户管理列表标签、用户详情 | 复用按用户查询，不虚构全局在线会话接口；恢复后保持停用 |
| 资格条件 | 会员等级页内独立标签与按等级筛选 | 条件读写权限独立；只有条件权限时仍可访问允许的标签和必要安全等级选项 |
| 来源规则、三级矩阵 | 分佣政策详情标签 | 属于具体政策，已发布内容只读；固定额和比例均受行预算约束 |
| 分佣总开关 | 分佣政策页的独立区域 | 与政策读写分开授权，只有开关权限也可进入；不伪装为政策版本字段 |
| 订单工作视图 | 订单履约页的全部、待接单、待发货、待虚拟交付视图 | 服务端筛选先于分页，视图间不重复实现状态机或另建主状态 |
| 库存、钱包、积分、业务事件流水 | 对应对象详情 | 只读不可变事实，分页且不开放人工删除；不能把普通账户列表归类为日志 |
| `product_purchase_limits`、`product_purchase_records` | 会员档案详情中的限购记录，支持商品筛选；商品详情提供带条件跳转 | 本计划补只读查询，不开放改累计量；退款不恢复终身累计购买额度 |
| `product_reviews` | 后续评价管理专项 | 本计划不开放菜单；已有表不等于管理查询、图片、审核或删除已实现 |
| `cart_items` | 消费者内部业务 | 不开放后台代改购物车 |
| `user_addresses` | 消费者地址簿；履约读取订单地址快照 | 不普遍开放全量地址簿，不因用户改地址改写历史订单 |
| `user_external_identities` | 认证内部支撑 | 不对普通运营展示完整 OpenID/UnionID，不任意修改绑定 |
| `user_refresh_tokens`、`admin_refresh_tokens` | 会话轮换和撤销内部支撑 | 不展示令牌或摘要，不单独建菜单 |
| 个人资料、修改密码、退出 | 右上角账号菜单 | 保留现有认证、错误传播和个人设置行为 |

上述菜单与页内/内部归属覆盖字典 67 张表；本计划不以覆盖表数量为由开放敏感数据或新增写权限。

### 7.3 路由、权限与工程组织

1. 导航由 `config/routes.ts` 与 `src/access.ts` 维护，不建立数据库菜单配置。一级分组以任一可访问子项为可见条件，默认落点选择有权页面；首页始终可供已登录管理员进入。
2. 优先保留现有 URL 和 Feature 文件，菜单分组不强制等于 URL 前缀。P0 登记现有链接、父路由、详情跳转和菜单高亮的迁移映射；如确需变更路径，同批更新所有调用方，不建立无期限兼容路由。
3. 保留现有 `catalog`、`trade`、`distribution`、`users`、`admins`、`roles`、`assets`、`settings`、`security`、`system`、`account`、`welcome` 实现；新增会员、政策和任务页面按真实内聚关系组织，不为菜单机械搬迁所有文件。
4. 复用 `PageFrame`、`ResourceTable`、`CommerceList`、`StandardConfirmModal` 和现有上传组件，先检查适用接口和实际样式接入。跨 Feature 复用只经公开入口或公共组件，不穿透内部实现。
5. 继续使用唯一 `src/lib/api/http.ts` 处理 Cookie、CSRF、Refresh、解包与错误；API 适配层消费生成 DTO，TanStack Query 保存服务端事实，不复制余额、权限或状态到 Store。
6. 标签和区域按独立读权限加载，只有条件、开关、日志或导出权限的组合均需核对；必要的关联选择器由后端提供最小字段投影和准确授权，不能为加载下拉框要求无关管理权限。
7. 既有权限码继续复用。新资源先在 Backend 源码目录登记准确 read/export 权限并补拒绝测试，再生成契约；不能用 `orders:read`、系统概览权限或“已登录”代替新资源授权。
8. 权限数据库同步沿用受控 `scripts.sync_permissions --check/--apply`，不在应用启动自动写表，不自动扩权普通角色。目标环境同步需单独核对环境与授权；不阻止独立源码实现和轻量检查。

### 7.5 关键业务展示与操作边界

- 商品维持稳定 SKU 身份；规格转换使用专用命令并说明旧 SKU 归档和库存清退，不通过改显示文字伪造同一货品。品牌/公共属性更新不覆盖历史采用快照。
- 批发阶梯在 SKU 编辑维护；会员价格依字典的一口价优先和最近折扣覆盖，不允许分类一口价或折扣连乘。页面不维护第二个结算定价器。
- 平台运费按优惠后商品金额和省级配置计算；不称为重量阶梯，不把运费当成商品上架必要条件，不调用被阻断的旧模板试算。
- 订单主状态、接单状态、履约状态、退款申请和资金执行分别呈现。零元订单显示内部成交依据，不补造零元渠道支付/退款。
- 本期仅未发货实物/未交付虚拟可整单退款，包含原运费；未接单自动审核，已接单人工审核。未决或已完成售后阻断新履约，不提供发货后退货或部分退款。
- 渠道退款成功但补偿未完成时显示“退款已成功，售后处理进行中”。异常重复/迟到收款退款允许无申请，不回补正常订单权益。
- 会员可无等级；停用等级保留身份且不享新待遇。资格条件只沿用消费、积分与已建模邀请指标，不增加充值条件或声称有效邀请已经运行。
- 佣金显示真实距离、来源预算、候选额、实发及追回依据；已发布政策不可修改。全局开关不暂停历史已确认权益的结算，不重算旧单。
- 钱包区分佣金与消费轨道；佣金冻结权益不混同提现冻结。显示欠款及释放先抵债；提现批准与实际到账分开，线下完成必须使用独立权限和凭证。
- 只读任务页面不意味着调度持续运行，也不代替渠道成功证据。错误摘要与日志使用允许字段，不输出敏感信息。
