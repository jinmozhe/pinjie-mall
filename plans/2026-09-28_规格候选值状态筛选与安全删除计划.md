## 2. 关联需求

- `BASE-BE-004`：商城领域按数据所有权实现（规格属性与候选值生命周期、商品采用一致性保护）。

## 3. 背景

用户在 Admin 管理端管理公共规格属性候选值时，发现批量停用后候选值状态变为停用，由于抽屉顶部缺少状态筛选，停用数据不易直观查看或找回；同时用户希望支持对无用的候选值直接物理删除，但担心是否因商品引用而只能停用。

经系统模型与电商架构分析确认：

1. 停用机制用于保障既有商品 SKU、历史订单与售后快照的稳定性，业务含义为“老商品保留，新商品不许选用”；
2. 零商品引用的候选值具备物理删除的业务安全性，数据库层面已有 `product_spec_values` 外键约束保护；
3. 用户已明确赞同并在会话中授权实施：在抽屉中增加状态筛选与行内快捷启停，并在后端支持未引用候选值的安全删除机制。

## 4. 目标

1. **抽屉状态筛选与快捷启停**：在 Admin 候选值管理抽屉顶部增加状态下拉筛选（全部/启用/停用），列表操作列支持一键切换启用或停用状态，解决“停用后找回困难”的问题。
2. **后端安全删除接口**：在 Backend 增加 `DELETE /admin/spec-attributes/{attribute_id}/values/{value_id}` 接口。若候选值已被商品采用（`ProductSpecValue` 存在引用），系统阻断删除并明确提示引用数量及建议使用停用；若未被任何商品采用，则执行物理删除并递增属性版本。
3. **契约同步**：更新 OpenAPI 契约并重新生成 `@pinjie/api-client`。
4. **前端删除能力**：在 Admin 候选值表格操作列增加删除按钮，带二次确认提示；已被引用的场景捕获后端明确提示并引导停用。
5. **门禁验证**：通过 Backend 轻量门禁（编译、Mypy、Ruff、导入边界）与 Admin 轻量门禁（typecheck、lint、boundaries），更新文档与计划索引。

## 5. 非目标

1. 不修改公共属性（`SpecAttribute`）本身的删除规则。
2. 不绕过外键强制级联删除已关联商品的候选值快照。
3. 不启动或修改小程序端和已停用的 Web 端代码。
4. 不在未获授权的情况下执行 Git 提交或推送。

## 6. 现状分析

1. **后端状态**：
   - `SpecAttributeValue` 模型存放公共候选值，`ProductSpecValue` 通过外键 `fk_product_spec_value_standard`（`ondelete="RESTRICT"`）关联候选值。
   - `catalog_service.py` 仅支持创建、更新、批量启停候选值，未提供删除端点。
2. **前端状态**：
   - `SpecAttributesPage.tsx` 中的 `ValuesDrawer` 抽屉仅有搜索框，无状态筛选。
   - 表格操作列仅有“编辑”按钮，要停用或启用需要勾选复选框再点顶部批量操作，流程较长。
   - 表格无删除按钮。

## 7. 方案设计

### 7.1 Backend

1. **Repository 层 (`catalog_repository.py`)**：
   - 增加 `count_standard_value_adoptions(value_id: UUID) -> int`，统计 `ProductSpecValue.value_id == value_id` 的记录数。
   - 增加 `delete_standard_value(row: SpecAttributeValue) -> None`，从 session 中移除候选值实体。
2. **Service 层 (`catalog_service.py` & `commerce.py`)**：
   - 增加 `delete_value(attribute_id: UUID, value_id: UUID) -> None`：
     - 获取目录锁；
     - 校验属性存在性及候选值归属；
     - 查询 `count_standard_value_adoptions(value_id)`，若大于 0 则抛出冲突异常：“候选值已被 X 个商品采用，不可删除，请使用停用”；
     - 执行物理删除，递增 `attribute.revision`，保存属性实体并提交。
3. **Router 层 (`catalog_router.py`)**：
   - 增加 `DELETE /admin/spec-attributes/{attribute_id}/values/{value_id}`，权限要求 `spec-attributes:update` 与 CSRF 保护。

### 7.2 契约与生成

- 后端导出最新 `openapi.json`。
- 运行 `pnpm generate-api` 重新生成 `@pinjie/api-client`。

### 7.3 Admin

1. **抽屉顶部状态筛选**：
   - 在搜索框旁增加 `Select` 下拉选择框：全部（不传）、启用（`true`）、停用（`false`）。
   - 过滤逻辑联动搜索词与状态：`(!normalizedValueSearch || ...) && (statusFilter === undefined || row.is_active === statusFilter)`。
2. **操作列快捷启停**：
   - 操作列提供切换按钮：当前启用的显示“停用”；当前停用的显示“启用”。
   - 点击调用 `commerceApi.updateAttributeValue` 或批量状态端点切换 `is_active` 并即时刷新。
3. **操作列安全删除**：
   - 操作列增加“删除”按钮，包裹 `Popconfirm`，提示“确认删除该候选值？若已被商品使用则会被系统拦截并建议停用。”。
   - 点击调用 `commerceApi.deleteAttributeValue`，成功则提示“候选值已删除”并刷新列表。若后端返回已引用冲突，直接就地展示错误说明。
