# Backend 端口迁移计划

## 1. 当前状态和结果

状态：已结束

结果：已完成；Backend 运行链路统一迁移到 `18168`，Backend 与 Admin 轻量门禁、治理检查和变更 Markdown 定向检查通过；全仓 Markdown 检查被既有 `.git/codex-git-sync/20260919-012500/pr-body.md` 阻断

## 2. 关联需求

无。本计划处理本机 Windows HNS 端口排除导致的运行配置冲突，不改变商城产品能力。

## 3. 背景

Windows 当前由 HNS/Hyper-V 保留 `7989-8088` 端口段，Backend 固定端口 `8000` 无法绑定。项目需要统一迁移到用户指定的 `18168`。

## 4. 目标

- Backend 本地、容器和生产运行链路统一使用 `18168`。
- Admin 代理、E2E 默认地址、健康检查和相关文档同步更新。
- 保持数据库、API 路径和业务行为不变。

## 5. 非目标

- 不修改 API 契约、数据库结构、权限目录或 Web 应用。
- 不启动、发布或部署生产服务。

## 6. 现状分析

- Backend、Admin 代理、Docker Compose、Nginx、E2E 脚本和运维文档存在 `8000` 运行地址。
- Admin 测试 Mock 中的 Backend 健康地址同步改为 `localhost:18168`；UUID、测试时间戳和其他无关数字不属于端口配置。

## 7. 方案设计

将真实运行链路中的 Backend 端口替换为 `18168`，容器内部端口、健康检查地址、Admin 代理默认地址和生产预览约束统一使用 `18168`。Admin 健康状态 Mock 同步使用该端口。

## 8. 全栈影响矩阵

| 范围 | 是否涉及 | 工作内容 | 前置依赖 | 验证 |
| --- | --- | --- | --- | --- |

| Documentation | 涉及 | 启动、部署和架构文档同步 | 运行链路完成 | Markdown 检查 |

## 9. 实施顺序

1. 更新 Backend、Admin、部署脚本和运维文档中的真实运行地址。
2. 搜索残留 `8000`，区分测试 UUID、测试 Mock 和历史架构示例。
3. 运行 Backend 与 Admin 轻量门禁及 Markdown 检查。
4. 回写本计划和索引。

## 11. 风险与回滚

风险：外部脚本或本机环境仍写死 `8000` 时，Admin 或健康检查可能无法连接。

回滚：将本次变更文件中的 Backend 运行端口统一恢复为 `8000`，不涉及数据库回滚。
