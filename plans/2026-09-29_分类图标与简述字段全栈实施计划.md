## 3. 背景

Admin 管理端当前富文本编辑器已落地（品牌描述、商品说明均已使用 Tiptap），分类领域 `product_categories` 表缺少图标和简述字段，小程序端后续需要在分类列表显示图标与简介。

图标方案确认为**方案二（自定义上传图片）**：与品牌 LOGO 完全一致，复用现有素材库上传组件，分类表新增 `icon_asset_id` 外键和 `description` 文本字段。

## 4. 目标

1. 数据库 `product_categories` 表新增 `icon_asset_id`（可空，关联 `assets.id`）和 `description`（TEXT，默认空字符串）两个字段。
2. 后端 API 同步新增字段：Schema 读写、服务层、路由、OpenAPI 导出。
3. Admin 分类管理页编辑器增加图标上传（复用 `BrandLogoPicker`）和简述 `RichTextEditor`。
4. OpenAPI 契约导出后重新生成 `packages/api-client`，Admin 适配新类型。

## 5. 非目标

- 小程序端分类图标/简述渲染（后续专项）
- 多级分类树结构调整

## 6. 现状分析

### 数据库

`product_categories` 当前字段：`id`、`name`、`parent_id`、`sort_order`、`is_active`、`revision`、`created_at`、`updated_at`。无图标和简述字段。

### 后端

- ORM：`apps/backend/app/db/models/product.py` 中的 `Category` 类
- Schema：`catalog_schemas.py` 中无 `CategoryInput`/`CategoryRead`（分类 CRUD 端点待确认实现位置）
- 路由：`catalog_router.py` 有 `/admin/product-categories/{category_id}/attributes` 用于规格模板，无分类基本信息 CRUD 端点

### Admin

- 分类相关 Admin 页面需确认路径

## 7. 方案设计

### 7.1 数据库迁移

新建迁移 `20260929_01_category_icon_description.py`：

```sql
ALTER TABLE product_categories
  ADD COLUMN icon_asset_id UUID REFERENCES assets(id) ON DELETE RESTRICT,
  ADD COLUMN description TEXT NOT NULL DEFAULT '';
CREATE INDEX ix_product_categories_icon ON product_categories(icon_asset_id)
  WHERE icon_asset_id IS NOT NULL;
```

### 7.2 后端 Schema 新增字段

`CategoryRead` 增加：

- `icon_asset_id: UUID | None`
- `icon_url: str | None`（服务层联查）
- `description: str`

`CategoryInput` / `CategoryUpdate` 增加：

- `icon_asset_id: UUID | None = None`

### 7.3 Admin

- 分类编辑弹窗新增「分类图标」字段（`BrandLogoPicker`）
- 新增「分类简述」字段（`RichTextEditor`，`minHeight=100`）
- 列表「简述」列使用 `plainTextPreview` 处理

## 11. 风险与回滚

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| `icon_asset_id` 外键约束影响现有分类数据 | 低 | 低 | 字段可空，不影响现有行 |
| Schema 破坏性变更导致前端失败 | 低 | 中 | 新增字段有默认值，向后兼容 |
| 迁移 downgrade 丢失数据 | 低 | 低 | 字段默认空，downgrade 直接 drop |

**回滚**：`alembic downgrade -1` 即可回滚，无数据损失风险。
