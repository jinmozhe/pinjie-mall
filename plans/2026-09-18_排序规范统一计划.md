## 3. 背景

当前 `product_categories.sort_order` 字段设计有缺陷：

- 类型 `INTEGER NOT NULL`，默认值 `0`，排序方向 `ASC`
- 未设置排序的分类（默认 0）永远排在人工设置了正数的分类前面
- 语义矛盾：0 代表"未设置"，却获得了最高优先级

此外，部分大数据量列表查询（商品、订单、库存流水、分销提现等）混用了 `created_at.desc() + id.desc()` 或 `created_at + id` 等组合，而项目已采用 UUID v7（时间戳单调递增），`id DESC` 等价于 `created_at DESC`，双字段排序冗余，且 `id` 主键索引可以直接利用，无需额外 `created_at` 索引。

## 4. 目标

1. **sort_order 修复**：将 `product_categories.sort_order` 改为 `INTEGER NULL`，默认 `NULL`，排序方向 `ASC NULLS LAST`。语义：NULL = 未人工排序（自然沉底），数字越小优先级越高。
2. **大数据表排序统一**：商品列表、订单列表、日志流水等分页查询，统一改为 `id DESC`（等价于按创建时间倒序），移除冗余的 `created_at` 排序字段。

## 5. 非目标

- 不修改 `product_images.position` 字段（该字段是强制赋值的有序位置编号，设计正确）
- 不引入新的分页机制，不改变 API 契约中排序参数
- 不执行 pytest、Playwright 或生产迁移（轻量门禁验证）

## 7. 方案设计

### sort_order 改造

1. 模型：`nullable=True, default=None`，Python 类型 `int | None`
2. Schema：`sort_order: int | None = Field(default=None, ge=0, description="排序权重，值越小越靠前，NULL 表示未设置自动排最后")`；去掉负数支持（`ge=0`），Admin 传 null 即可
3. Repository：`order_by(Category.sort_order.asc().nulls_last(), Category.id.desc())`
4. 新增 Alembic 迁移：ALTER TABLE 将列改为 nullable，去掉 DEFAULT，更新列注释
5. Admin 前端：表单初始值 `sort_order: null`，InputNumber 改为 `min={0}`，不设 required，允许清空

### 大数据表排序改造

Repository 层统一将 `created_at.desc(), id.desc()` → `id.desc()`，`created_at.desc(), id` → `id.desc()`，`created_at, id` → `id`（正序保留语义，仅删冗余字段）。
