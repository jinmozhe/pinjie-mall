## 目标、范围与授权

用户于 2026-10-09 同意集中存放设计资料并要求直接创建，同时提出先确认截图再制作可编辑原型。第一批首页、商品详情与 SKU 的视觉风格已获用户确认。用户随后要求一次性交付全部小程序界面的图片，尽可能覆盖分类、购物车、结算、个人中心、订单、地址、钱包等，并读取现有后端接口对齐交互。本轮范围扩为全页面与关键状态的静态设计图和图片浏览目录，HTML/CSS 交互原型延至整套图确认后。

不初始化 Taro 工程，不修改 Backend/Admin、契约、数据库和部署，不启动 Web 服务，不提交或推送 Git。

## 影响范围与文件

Documentation 涉及 `docs/design/miniapp/`、UI 规范、文档索引、项目索引、目录说明、Changelog 和本计划及计划索引。Backend、Admin、Web、API Client、Database、Deployment 均不涉及，不改变应用运行行为；后续 HTML 仅为离线设计资料。

## 实施顺序

1. 登记计划和设计权威入口。
2. 按现有规范绘制三张 750 宽 PNG 及并排总览；商品与价格明确标为设计示例。
3. 核对图片、尺寸、文案、弹层和索引，运行适用轻量门禁。
4. 收集用户对布局、主色、商品卡片和详情/SKU 的反馈。
5. 读取根 OpenAPI 与后端 Router、Schema、业务状态，建立页面与当前能力的映射，区分已有接口、展示缺口与目标流程。
6. 一次性生成全部小程序页面、关键弹层和业务状态图，并生成离线图片浏览目录和分组总览。
7. 核对页面、布局与映射后交付，整套图确认后再制作 HTML/CSS 交互原型。

## 风险与回滚

静态图不能证明 NutUI、微信原生导航、交互和真机表现，原生栏仅为示意；商品插画为自绘占位，金额和规格为设计示例。保留前一版设计文件，后续采用版本文件名，不覆盖已确认版本。当前新增设计资产可逐文件撤回，计划永久保留。

## 实施结果与剩余问题

第一批 V1 静态设计图与总览已交付，设计说明、流程、绘图脚本及相关索引同步完成。首页图表现首屏，后续商品卡片需要滚动查看；详情图也仅展示首屏。程序化绘图直接生成 PNG，没有运行浏览器或微信工具，没有启动服务，也未生成项目缓存。

V2 全套页面与业务状态图已交付，共 188 张独立图与 36 张总览，覆盖浏览、购买、订单履约、售后评价、个人身份、地址、会员推荐、钱包提现、服务与通用状态十个模块；离线图集、完整目录、绘图脚本和能力映射已同步。本轮只读后端源码和唯一根契约；当前私有接口仍使用浏览器 Cookie，本人订单列表、分类过滤、部分查询展示、积分 C 端查询与微信 Bearer/真实渠道仍有缺口，已在映射说明和逐页设计边界中标注，未借 Admin 接口冒充 C 端能力。

本轮没有启动服务、监听端口或打开测试浏览器，没有新增项目程序缓存；修订时的字节备份使用系统临时目录并已自动清理。Git 未提交或推送，先前文档任务的本地修改保留。整套图的内容与流程等待用户评审，业务 HTML/CSS 原型和微信实现尚未执行；计划保持实施中，不将设计图视为可运行商城。
