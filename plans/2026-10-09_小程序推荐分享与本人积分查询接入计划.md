# 小程序推荐分享与本人积分查询接入计划

## 1. 当前状态和结果

- 状态：已结束
- 结果：已完成；推荐分享、原码恢复与本人积分源码、生成契约、轻量门禁及文档已交付，AppID 预留，平台/数据库与重型验收未执行。

## 2. 关联需求

- BASE-COM-301、BASE-COM-302、BASE-BE-003、BASE-API-001、BASE-API-002、BASE-QUAL-001。
- 小程序 MP-REF-001、MP-PTS-001；积分查询复用既有会员积分账本，兑换、抵扣、到期及有效邀请奖励政策不在本期开放。

## 3. 背景

用户尚未取得微信 AppID，要求继续预留 AppID 开发功能，申请完成后再本地平台验收。资料、会员和钱包已具备源码，推荐关系和积分缺少消费者安全投影及页面。

## 4. 目标

接入本人推荐码、主动确认首次绑定、分享落地意图、绑定未知结果查询，以及本人积分账户和分页流水。

## 5. 非目标

不升级依赖，不改变真实登录、支付或提现开放状态；不实现有效邀请奖励、积分兑换/到期/抵扣、注销或设备管理。不执行 Git 交付、微信编译、平台测试、动态数据库验证或发布部署。

## 6. 现状分析

DistributionService 已提供图锁、首次绑定、同码幂等、自邀与循环保护。积分账户与不可变流水已存在。小程序采用锁定 Taro React/NutUI/Query/Sass，AppID 为 touristappid，微信登录默认关闭。

## 7. 方案设计

- 新增 MiniappBearer 本人推荐查询及绑定，复用公开领域写服务，只投影本人码、绑定时间和指定码是否匹配，排除他人身份。
- 分享只携带邀请码到固定推荐落地页；参数仅为意图，登录后仍显式确认，不在页面加载时绑定。
- 不将分享调用认定为发送成功或奖励事实；未知写结果只查询指定码的关系匹配，未绑定时保留原码并仅允许主动同码恢复。
- 本人积分查询先检查 active user，再按本人 account_id 分页。无账户明确为空状态；积分采用十进制字符串避免 JavaScript 大整数丢失精度，流水不暴露内部来源 ID、备注或幂等键。
- 官方核验：2026-10-09 已读取微信 Page.onShareAppMessage 与 Taro Hooks 官方现行页面，使用 enableShareAppMessage、useShareAppMessage、原生 openType=share、useRouter 参数；技术栈维持现有锁定版本。

- 新增四个 Bearer 操作：推荐查询、主动绑定、积分账户与流水；复用既有领域写事务和模型，无新迁移或依赖。

- 积分账户、三类变动与来源分类来自本人安全投影，大整数传输为字符串；无账户和真实空流水分开展示。
