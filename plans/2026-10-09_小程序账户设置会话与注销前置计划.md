- 结果：已完成；三个页面、四个本人接口、原集合恢复、生成契约及文档已交付，适用轻量门禁通过；实际注销关闭，AppID 预留，平台/数据库与重型验收未执行。
- 关联需求：BASE-BE-003、BASE-MP-001、BASE-API-001、BASE-API-002、BASE-QUAL-001；MP-AUTH-004、MP-AUTH-005、MP-PRIV-001。

## 背景与目标

已接入本人资料和交易，账户设置、本人会话管理与注销前置仍缺少小程序入口。补齐设置、分页会话、单个及批量撤销、未知结果恢复、隐私入口与只读注销状态核对。

## 非目标

- 实际注销、权益放弃、身份解绑或旧账号绑定；不新增 DELETE 账户端点。
- 真实 AppID、登录总开关开启、数据库升级、支付提现与发布部署。
- 搜索营销、依赖升级、Web、重型测试及 Git 提交推送。

## 现状分析与方案

- 复用 UserSession 与既有 miniapp_bearer Profile，不把登录会话称作可信物理设备，不展示原始 IP、User-Agent、凭据或身份映射。
- 分页读取本人小程序会话，额外提供最多 100 个仍有效的其他会话 ID 与总数。撤销请求接受用户已确认的明确 ID 集合，拒绝重复、当前、他人及 Browser 会话；事务内锁用户后复核当前会话，按固定顺序锁目标。
- 撤销状态由 Session 权威事实裁决；Refresh 同样拒绝已撤销 Session，无需等待 Access 到期。安全事件与撤销同事务写入，失败全部回滚。
- 原目标 ID 在发送前按本人账户保存，未知结果先查原目标，不自动重放；用户可主动同集合恢复，不把新登录会话加入原意图。
- 注销核对采用明确只读聚合，仅返回本人需要核对事项，未开通钱包和积分不伪造余额。各项是咨询线索，不是最终注销资格；全部为零仍保持自助注销关闭。
- 页面沿用现有 tokens、Button、AuthGate、QueryState、安全区与公开帮助入口；隐私说明和设置公共部分不要求登录。

## 风险与回滚

- 会话撤销会使原会话失效，前端必须说明目标和后果；已撤销凭据不能由回滚恢复。
- 注销核对通过单条 SELECT 提供同一语句快照，响应之后仍可能变化，最终权益处置不能据此作决定。
- 可撤回新增页面和接口；不删除业务历史、不重置余额、不恢复已撤销会话。
