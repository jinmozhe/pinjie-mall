- 结果：已完成；独立商城身份、两端交付链路和 Web 冻结入口已校正，适用轻量门禁通过。

## 2. 关联需求

## 3. 背景

只读核对发现 Web 仍进入生产编排及发布验证入口，发布脚本仍绑定母版，README 和 PRD 存在母版与商城身份冲突。

## 4. 目标

1. 本仓库独立维护、运行与发布，不依赖母版目录、仓库、凭据或镜像。
2. C 端仅为微信小程序，前阶段只推进 Backend 与 Admin，小程序工程后续实施。
3. 冻结保留 Web 源码，阻断启动、构建、测试、发布与部署入口。
4. 同步权威文档和可执行门禁，纠正此前计划完成范围的记录。

## 5. 非目标

- 不实现商品、库存、订单、支付、分销等电商核心业务。
- 不开发小程序，不改变既有业务 API、数据库模型或管理后台 UI。
- 不修改真实环境文件、母版仓库、远端资源、生产数据或 Git 历史。
- 不提交、推送、发布镜像、部署或执行重型验证。

## 6. 现状分析

- Git origin 已指向商城独立仓库。
- 根 dev 已限定 Admin，生产 Compose 仍保留默认启用的 Web 容器。
- CNB、TCR、发布证据及相关夹具仍引用母版身份。
- 需求文档将电商能力同时列入目标和非目标，README 仍宣称 Next.js 用户端。

| 规则来源 | 适用约束 | 落实位置 | 验证方式 |

## 11. 风险与回滚

- Web 入口阻断属于预期行为，原有 Web 源码保留在仓库。
- 发布模板使用独立商城身份；远端资源和 Secrets 未配置时应明确失败，禁止回退母版。
- Backend 身份默认值变化可能使使用旧默认 issuer 的会话失效；不修改真实配置，不自动迁移会话。
- 本次不改变生产状态。回滚只反向应用本任务差异，保留用户新修改和全部计划资产。
