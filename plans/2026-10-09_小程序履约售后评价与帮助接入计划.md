# 小程序履约售后评价与帮助接入计划

## 当前状态和结果

- 状态：已结束
- 结果：已完成；源码、生成契约、轻量门禁与文档已交付，平台、数据库、渠道及重型验收未执行

## 关联需求

BASE-COM-103、BASE-COM-104、BASE-COM-105、BASE-COM-203、BASE-COM-204、BASE-COM-205、BASE-BE-003、BASE-MP-001、BASE-QUAL-001；对应 MP-ORD-002、MP-FUL-001、MP-AFT-001、MP-AFT-002、MP-REV-001 与 R1 帮助入口。

## 背景与目标

基础交易已有源码，履约、售后与评价写服务已存在，尚缺小程序 Bearer 入口和消费者展示。复用既有事务服务，完成本人订单组合状态分页、履约详情与确认收货、整单退款申请与恢复及记录详情、明细评价与结果确认、公开帮助和可配置联系信息。

## 非目标

不变更订单主状态或退款政策，不实现部分退款、实时物流、聊天、订阅消息、钱包、会员、推荐和支付；不执行迁移、渠道操作、发布、部署或 Git 写动作。

## 实施结果

新增十个小程序路径，旧端点与已有 Schema 的语义对比无变更。MiniappTradeQueryService 实现本人组合状态分页、批量加载明细/评价/退款资格、售后列表/详情/原请求确认，资金投影不暴露运营渠道标识。写端点复用 LifecycleService，保留原事务和政策。

小程序新增五个 service 分包页面：整单申请、售后列表、售后详情、评价、帮助。订单接入履约/成交事实、确认收货和评价；个人中心增加履约与售后入口，未登录也可访问帮助。退款发送前保存按用户与订单隔离的原意图，受理确认后清除，查询失败不重放，明确同键重试；写入已确认但本机清理/跳转失败时显示已受理。评价提交后读事实，不自动重复提交。支持联系方式配置或明确缺失，沿用 tokens 和生成类型，未调整依赖、数据库模型或 Admin 流程。
