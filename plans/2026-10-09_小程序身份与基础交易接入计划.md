- 结果：已完成；身份与基础交易及受限内容源码和轻量门禁已交付，真实迁移/平台及重型验收未执行，系统临时缓存清理受策略阻止

## 背景

小程序公开浏览已实现，私有端点仍使用 Cookie 与 CSRF。用户授权继续实现身份、地址、购物车、结算、订单及商品富文本，AppID 尚未准备好。

## 目标

实现可信微信换码、无密码建号、独立 Bearer 会话、内存凭据与冷启动重新换码、退出和失效处理；接通本人地址、购物车、服务端报价、幂等下单、订单分页筛选、详情和取消；新增说明内容严格校验与历史显式迁移工具，以 mp-html 渲染已符合策略的说明。

## 非目标

微信支付、退款渠道、提现、分销页面、自动绑定旧账户、游客购物车、Web/H5、生产发布、Git 动作、真实数据库迁移、pytest/Vitest、生产构建、平台自动化及真机验收均不在本轮。AppID 与服务端秘密缺失时微信登录明确不可用，不提供模拟身份或公共密码。

## 现状分析

users 密码可空，外部身份表与 miniapp_registration 配置已有迁移；UserSession 只允许 browser_cookie。购物车、地址、报价和订单事务已存在，需独立身份入口、购物车展示投影、本人订单分页与 request_id 查询。description 既有数据未审计，不能直接启用 HTML 渲染。

## 方案设计

- 小程序端点固定 /miniapp 前缀、独立签名/HMAC 密钥和 audience，显式拒绝 Cookie；Admin 与存量 Cookie 路由不改变。会话表新增准确 profile/client/CSRF 成组约束，历史 Cookie 会话继续受原入口保护，不作为小程序迁移回退。
- 服务端共享异步 HTTP 客户端调用微信 code2Session，无自动换码重试；code、AppSecret、session_key、Token 和外部原文不记录。可信 OpenID 并发建号由事务锁与唯一约束保护，首次建号配置共享锁，已有身份不受注册开关影响。
- Access/Refresh 仅在小程序私有内存；进程冷启动通过新的微信 code 恢复身份，用户主动退出后需再次主动登录。刷新单飞并轮换，身份代次阻止旧响应与写操作跨账号重放。
- 私有交易复用现有 Application Service；价格与库存由后端裁决。下单结果未知时保留相同 request_id 与内容，仅查询或用户显式以原键恢复，不自动创建新订单。
- description 使用受限 HTML v1；新写入严格拒绝非法标签/属性。旧记录标记 legacy，前台不渲染；提供明确 text/html 来源的迁移 dry-run/apply，不猜测格式、不静默清洗。负责人 jinmozhe，2026-10-23 前完成数据审计迁移并另行删除 legacy 标记窗口，未迁移记录持续不可渲染，禁止无期限双读。
