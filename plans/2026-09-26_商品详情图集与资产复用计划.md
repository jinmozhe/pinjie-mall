## 3. 背景

商城消费者唯一客户端是微信小程序。现有商品说明为纯文本，主图与轮播图引用统一资产。详情需要有序切片图片，优先复用资产管理与原生图片展示能力，避免引入 HTML、Markdown 或富文本运行时及其跨端兼容负担。

## 4. 目标

1. 建立“纯文本商品说明、主图轮播、独立详情图集、结构化规格参数”的内容分工。
2. Admin 支持选择已有资产、多文件上传队列、任意位置排序、单张与批量移除、手机宽度预览和一次保存。
3. 商品保存资产引用，沿用权限、revision、事务、审计和资产删除保护。
4. 补齐可信图片尺寸，公开商品详情提供有序 URL、宽高，供后续小程序预留布局空间。
5. 保持现有技术栈、文件公开访问和补偿机制，不改变既有商品数据含义。

## 5. 非目标

- 不安装富文本、Markdown、HTML 清洗、拖拽或新的上传 SDK，不升级 React、Umi、Ant Design、ProComponents 或 Pillow。
- 不建设自由图文混排、自动切图、在线修图、任意外链抓图、视频、页面装修、云存储或私有素材发布系统。
- 不初始化小程序，不修改或启动冻结的 Web，不监听 3000 端口。
- 除本机开发库已授权的升级与历史资产回填外，不执行数据清理、生产操作或远端交付。
- 不自动运行 pytest、Vitest、production build、Playwright、浏览器自动化、测试库迁移或真机验证。
- 不自动暂存、提交、推送、创建 PR、发布镜像或部署。

## 7. 方案设计

### 7.1 内容、关系与契约

- 保留 `description` 的纯文本语义及 20,000 字符限制，不转 HTML、不截断旧内容，不将价格和售后规则的权威来源转入描述图片。
- 保留 `image_asset_ids` 和公开 `images` 的轮播语义及上限。
- 新增 `detail_image_asset_ids` 完整有序集合。创建允许空集合；更新明确要求提交，避免旧请求缺字段时静默清空。输入契约变化与 Admin 同步交付，并核对 Breaking Change，不引入长期双轨。
- 新增 `product_detail_images(product_id, asset_id, position)`，沿用图片关系的复合主键、位置唯一、非负位置、资产索引与外键 RESTRICT。`position` 表示集合内连续序号，不另建排序权重。
- 单个详情集合内资产不重复；允许跨商品复用，也允许同资产分别用于轮播和详情。
- 旧商品详情初始为空，不自动复制轮播图。空详情不增加新的上架阻断，保留既有可售规则。

### 7.2 图片预算与可信尺寸

以下是本计划拟定的首期详情绑定预算，属于保守产品约束，尚无真机性能证据；执行确认包含对这些默认值的认可。

| 项目 | 拟定标准 |
| --- | --- |
| 数量 | 0 至 20 张，独立于轮播图 |
| 格式 | JPEG、PNG、WebP，沿用 product 场景白名单 |
| 单图体积 | 不超过 2 MiB |
| 整组体积 | 不超过 20 MiB，按资产字节数求和 |
| 单边像素 | 宽、高均不超过 4096 |
| 总像素 | 每张不超过 8,000,000 像素 |
| 尺寸来源 | 服务端解码得到的正整数 width、height |

上述预算只约束新详情绑定，不下调现有 product 上传和主图业务限制。上传预检改善反馈，后端对已有和新上传资产执行同一权威校验；超限明确拒绝，不静默压缩、截断或丢图。

资产新增可空 width、height 和 frame_count，约束三者同时为空或同时为正数。非图片与未处理历史资产可为空；新详情引用必须具备可信尺寸。新 product 图片在私有 staging 阶段完成 MIME、解码完整性和尺寸核验再公开提交，保留失败补偿。解码使用已安装 Pillow，在线程中以单实例单并发、10 秒队列等待、单边 8192、最多 20 帧及像素乘帧数 2000 万的上限执行；处理资源上限与详情绑定预算分开，不以详情预算拒绝原本合法的轮播素材。

实施前核对既有图像校验实现和锁定 Pillow API，明确 EXIF 方向及多帧策略，保证记录尺寸与实际展示一致。详情限定静态内容，不以只读文件头冒充完整解码验证，不扩大其他文件场景。

### 7.3 历史图片、迁移与回填

- Alembic 新增表、尺寸列及约束，不在迁移中遍历或解码磁盘文件。
- 独立回填工具默认只读检查，显式应用模式才更新指定资产或有界批次；报告成功、缺失、损坏及冲突，不输出秘密。
- 通过存储端口读取受控文件键，不从 URL 抓图、不引入绝对路径依赖。必要的端口扩展同步适配本地驱动和测试替身。
- 解码与短事务写入分开，写前锁定资产并复核文件键和哈希，防止与删除或其他更新竞争。失败不伪造尺寸、不自动删文件。
- 回填未执行时保留旧主图和说明行为。缺少尺寸的旧资产不能新绑定为详情；Admin 明确提示补齐元数据。查询不执行隐式回填，不返回伪造尺寸。
- 默认交付迁移、回填工具及操作说明源码；执行数据库升级和回填前独立核对目标、备份、迁移人工审查及授权。

### 7.4 事务、权限与生命周期

- 沿用商品权限、管理员会话、CSRF、ManagementAuditCoordinator 和 revision。
- 跨领域用例合并主图与详情资产 ID，去重后按固定 UUID 顺序加锁，校验 admin/system 主体、product 场景、类型和详情预算；批量上架先汇总整个批次并一次锁定，再逐商品校验，避免与资产批量删除交叉死锁。
- 商品资料、两套关联和审计在同一事务内写入；失败保留旧数据。禁止旧 revision 覆盖新内容，审计不记录图片二进制和完整说明。
- 单删及批量硬删在移动文件前检查详情、轮播及其他引用；外键继续兜底，绑定与删除共用资产行锁及既有补偿。
- 移除图片仅解除关联，取消编辑不硬删文件；已上传未绑定资产交给现有管理员清理流程，不新增自动清理任务。

### 7.5 Admin 编辑与上传队列

- 商品编辑内分开呈现文字说明、轮播及详情，保留规格与其他业务表单；使用现有 Ant Design 6、ProComponents 和主题。
- 支持资产分页搜索及多选、多文件上传、缩略图、序号、尺寸/大小、上移/下移/置顶/置底、单张/批量移除、手机宽度预览；首期不依赖拖拽库。
- 串行受控队列按选择时的稳定序号排列，失败重试保留位置，取消或卸载后不得污染其他商品草稿。命中同一资产时明确提示，不重复绑定。
- Upload 经 `adminApi.uploadAsset` 调用现有 HTTP 管道，不另建 XHR 认证、客户端或 Token 存储。网络结果未知按既有主体与哈希去重语义处理，不无限自动重试。
- 上传中或有未处理失败项时禁止保存；允许重试或经确认移除。最终一次提交完整商品关联，文件上传队列不冒充业务批量事务。
- 移除复用 StandardConfirmModal，说明保存后解除关联且原文件保留。提交防重、禁止关闭，失败保留草稿；明确区分写入成功与刷新失败。
- 已选图片展示不依赖当前资产分页。管理商品详情输出必要展示元数据，资产库选择继续受 assets:read 限制，不借预览开放整个资产库。
- 预览只模拟内容顺序、比例和换行，不表述为小程序真机验收。

### 7.6 API 与小程序展示

- 管理写入仅接受资产 ID。公开详情返回有序 `detail_images`，每项含受控 URL、width、height，不暴露上传主体、文件哈希和存储键。管理读取按编辑需要提供 asset_id、字节数等字段。
- 详情图只进入商品详情查询；共用列表/详情 Schema 时建立明确详情模型并适配消费者，避免列表膨胀和 N+1。
- 按“Backend、根 OpenAPI、API Client、Admin”生成和适配，禁止手工修改生成文件或复制 DTO。
- 资产继续保存受控站内路径。后续小程序通过已配置的可信 HTTPS 资源基址解析相对路径，不依赖 Admin Origin、不保存本机路径；绝对 URL 遵守统一可信域名策略，不增加任意来源回退。
- 后续小程序用原生 Text/Image，图片 widthFix、等宽、按尺寸占位、下方懒加载、失败反馈及点击预览。切片默认无缝连续，间距由组件统一控制。
- React/Taro 候选、WebP、基础库和真机性能留在后续小程序专项。共享生成类型，不共享 Admin DOM 代码或 React 实例。
- 上传即公开，下架不撤销文件 URL；私有素材发布不在本方案内。
