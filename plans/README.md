# 全栈实施计划规范

`plans/` 是整个全栈 Monorepo 的实施计划目录，统一覆盖 Backend、Admin、Web、API Client、Database、Deployment 和 Documentation。

全部实施计划的永久登记见 [INDEX.md](INDEX.md)；当前活动计划见 [../PROJECT_INDEX.md](../PROJECT_INDEX.md)。

计划以一项完整业务能力或工程目标为单位。跨应用功能必须在同一份计划中描述完整链路、实施顺序、契约同步和联合验证，不按 Backend、Admin 或 Web 拆分目录。仅影响单个范围的任务仍属于仓库级计划，并在全栈影响矩阵中明确其他范围不受影响的原因。

## 计划创建条件

新增产品能力、跨应用或共享契约变更、依赖调整、数据库模型或迁移、CI、发布或部署流程、安全或权限边界、架构决策、治理结构调整，以及需要多阶段追踪的任务必须创建或续接计划。

目标明确、影响局部、可通过现有轻量门禁验证且不触及上述边界的小修复、样式调整、普通配置勘误和文档勘误不要求新计划；修改前简述范围与验证方式即可。已有匹配活动计划时继续更新原计划。不能仅因涉及多个文档或修改了一条规则就套用完整计划。

计划用于记录方案与执行，创建计划本身不增加审批。用户已明确要求实现、修复或优化，且目标和边界可从上下文确定时，在用户确认记录中引用该授权后直接推进。只有关键产品取舍、无法推断的验收边界、新增高风险动作或用户要求先审方案时，才等待对应确认；其余独立工作继续。

## 命名规范

```text
YYYY-MM-DD_功能简洁名称计划.md
```

计划文件直接放在 `plans/` 下，不创建 `active/`、`archive/` 或按应用划分的子目录。

## 状态与结果

计划只使用以下四种状态：

| 状态 | 含义 | 执行要求 |
| --- | --- | --- |
| 待确认 | 存在影响实施的关键问题或未获授权动作 | 暂停依赖该问题的实施，可继续只读准备和独立的已授权工作 |
| 待实施 | 待确认问题为“无”且用户已明确授权 | 可以开始实施 |
| 实施中 | 已开始修改，尚未完成交付 | 优先继续同一计划并持续回写结果 |
| 已结束 | 本计划不再继续实施 | 必须填写结束结果和事实依据 |

待确认、待实施和实施中的计划结果统一填写 `不适用`。“已结束”计划的结果必须以 `已完成`、`已取消` 或 `已替代` 开头，后面可以使用分号补充事实。阻塞、等待依赖和验证失败写入“剩余问题”，不增加新的状态。

## 固定结构

跨栈或高风险计划使用以下完整结构；其他确需计划的任务可合并章节，但必须记录目标与范围、授权依据、影响文件、实施步骤、风险与回滚、验证、状态与结果。不得为填充模板虚构需求、ADR 或无关交付物。

完整结构：

1. 当前状态和结果
2. 关联需求
3. 背景
4. 目标
5. 非目标
6. 现状分析
7. 方案设计
8. 全栈影响矩阵
9. 实施顺序
10. 影响文件
11. 风险与回滚
12. 验证清单
13. 待确认问题
14. 用户确认记录
15. 实施结果
16. 剩余问题

“关联需求”引用 `docs/PROJECT_REQUIREMENTS.md` 中一个或多个 `BASE-*` 编号。治理前置、纯修复或无法对应现有需求时，填写“无”并说明原因；不得为满足格式虚构需求编号。

## 确认与完成条件

关键待确认问题为“无”且已有用户授权覆盖实施范围时，计划可进入“待实施”或“实施中”，无需额外确认计划文字。可自行决定的实现细节记录为方案；尚未授权的发布或部署明确列为非目标，不阻塞独立的本地实现。跨栈计划必须明确实现顺序和契约生成顺序。

计划标记为“已结束 / 已完成”前必须：

1. 回写实际实施内容、验证结果和剩余问题。
2. 更新计划原文和 `plans/INDEX.md` 中的状态与结果；只有活动计划发生变化时才同步 `PROJECT_INDEX.md`。
3. 当前系统行为变化时更新对应 `docs/` 文档。
4. 存在重大长期技术取舍时更新或新增 ADR；普通修复不强制生成 ADR。
5. 已交付能力或值得追踪的治理变化同步到 `CHANGELOG.md`；普通勘误不机械增加记录。
6. 检查 Backend、Admin、Web 和跨栈范围均已完成或明确记录不涉及。
7. 检查讨论中形成的已确认结论已按根 `AGENTS.md` 路由到对应权威文档，没有只保留在对话中或复制成多份事实来源。

完成条件以本次授权目标为准。轻量门禁通过且已按项目策略记录未执行重型验证时，可以完成本地实现计划；用户明确要求但尚未完成的验证或远端动作必须保留为剩余问题，不得标记全部完成，也不因未授权的可选后续动作无限保持活动状态。

## 计划文档保护

1. `plans/` 中已经存在的计划文档属于永久项目资产，AI 永远不得删除。
2. AI 不得移动、重命名或用新文件替换既有计划文档。
3. 计划发生变化时，只允许更新原文件中的状态、实施结果、验证结果、剩余问题和用户确认记录等内容。
4. `plans/` 中每份 `YYYY-MM-DD_*计划.md` 必须在 `plans/INDEX.md` 中保留唯一登记；`README.md` 和 `INDEX.md` 是治理文件，不进入登记表。
5. 已完成、已取消或已替代的计划仍需保留原文和索引，不得自动归档或清理。
6. 删除、移动和重命名计划文档只能由用户人工处理。AI 可以列出建议，但不得执行这些文件操作。
7. 用户人工调整计划文件后，AI 才能依据当前文件事实同步索引路径和状态。

## 计划资产保护

本仓库现存及后续新增的计划都是永久项目资产。计划只记录本项目的目标、验证和结果；外部仓库历史不构成本项目的运行、发布或计划依赖。
