- 结果：已完成；阶段 2 Backend、迁移、OpenAPI 与 API Client 已交付，适用轻量门禁通过

## 2. 关联需求

- `BASE-COM-006`：平台统一运费。

## 3. 背景

商品首期已交付 SKU、批发阶梯、规格身份和库存。旧报价、购物车、结算和下单入口已因模型迁移返回 `COMMERCE_UPGRADE_REQUIRED`。交易恢复前，服务端必须先形成可复用、可冻结的会员价格与整单运费结果。

## 4. 目标

- 新增会员等级、统一会员价格规则和小程序外部身份映射的数据模型与 Alembic revision。
- 改造会员档案为可空等级外键，保留推荐关系语义。
- 在固定 `system_settings` 分组中实现 `order_shipping` 配置和管理接口。
- 提供管理端会员等级、价格规则、运费配置接口，以及只读统一报价接口和可供后续订单快照使用的报价 DTO。
- 外部身份只提供可信渠道适配边界；未接入渠道和 Bearer 会话明确不可用。

## 5. 非目标

- Admin 页面、小程序工程、微信或其他实际渠道联调。
- 购物车、结算、订单、支付、限购、佣金、钱包和持久任务恢复。
- `commission_control` 消费逻辑和分佣政策，留在阶段 3。
- 本地或测试数据库实际迁移、pytest、并发动态测试和外部渠道测试，除非用户另行点名授权。

## 6. 现状分析

当前 ORM 已有商品首期的 52 张表，`member_profiles`、旧 `shipping_templates` 和旧认证会话存在。字典定义 `member_levels`、`member_price_rules`、`user_external_identities` 为目标运行表，平台运费复用 `system_settings.order_shipping`。现有旧交易入口已经阻断，适合在不兼容旧报价的前提下替换其后端依赖。

## 7. 方案设计

- 价格规则使用一张表保存 SKU、商品和分类范围；SKU/商品支持一口价、折扣和排除，分类只支持折扣或排除，数据库确保范围对象与金额参数互斥且唯一。
- 报价服务按 SKU 一口价、商品一口价、对应数量批发阶梯、分类链最近规则、等级默认折扣顺序计算，并以 Decimal 的四舍五入结果输出。
- 运费以优惠后实物商品总额和省级地区匹配 `order_shipping` 的整组覆盖或默认规则；虚拟商品为零运费，缺少或非法配置明确失败。
- 外部身份使用 `(provider, app_id, subject_id)` 与 `(user_id, provider, app_id)` 双唯一约束，不按 UnionID 自动合并；渠道适配器尚未配置时拒绝使用。
- 管理写接口使用精确权限、CSRF、revision、事务和审计；报价接口不返回成本价。

## 15. 实施结果

- 新增 `member_levels`、`member_price_rules`、`user_external_identities`，并将 `member_profiles` 从 `level_code` 迁为可空 `level_id`、等级变更时间和 revision。
- 新增固定 `miniapp_registration`、`order_shipping` 设置行，会员价格和平台运费管理接口均使用精确权限、CSRF、版本检查及审计。
- 新增 `POST /api/v1/commerce/quotes`，按当前用户等级、SKU/商品一口价、批发阶梯、最近分类规则、等级默认折扣和省级平台运费计算报价指纹；该接口不创建订单、不预占库存。
- 新增外部身份 Provider 协议及未接入渠道的明确 `503 / EXTERNAL_IDENTITY_UNAVAILABLE` 边界；未实现微信可信换码、小程序 Bearer 会话或实际渠道调用。
- 根 OpenAPI 已从 Backend 导出，`packages/api-client/src/` 已生成。
- 通过 Backend Ruff、格式、Mypy、导入边界、编译和应用导入，Admin typecheck/lint、工作区、边界、文档治理和本轮 Markdown 定向检查。
