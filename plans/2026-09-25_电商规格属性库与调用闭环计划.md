# 电商规格属性库与调用闭环计划

## 当前状态和结果

- 状态：已结束。
- 结果：已完成；公共属性库、分类模板与商品调用闭环、可复用重置脚本和本机开发库导入均已交付。
- 授权：用户明确要求实施已确认计划，包括本机开发库七张属性表清空重建、数据核验及本地可复用脚本；不包含 Git 提交、发布或部署。

## 关联需求

`BASE-ADMIN-004`、`BASE-COM-001`、`BASE-COM-002`、`BASE-COM-004`、`BASE-COM-103`。

## 背景与现状

现有七张属性表及公共库、分类模板、商品采用和规格转换服务已经存在。Admin 尚缺分类模板、商品属性与 SKU 编辑闭环。源 Excel 包含 1036 行候选，其中 73 行本地生活排除，963 行零售资料需要清洗；原编码存在异义冲突。

## 目标与非目标

- 清洗公共数据，逐行保留来源与处理结果。
- 补齐公共库查询及批量状态、分类模板和商品属性/SKU 操作。
- 描述属性集合维护和销售候选追加不重建已有 SKU、不改变库存。
- 交付受控开发库清空重建脚本、种子数据和运维说明，并实际导入开发库。
- 不新增业务表，不建设行业模板包、别名平台，不引入本地生活业务，不运行 Web 或实施小程序。

## 方案设计

公共属性统一保存类型与规则，分类模板和商品采用决定销售/描述用途。标准值按语义清洗，开放描述使用文本或数值；商品局部销售候选遵守采用权限。已有定义和值保留冻结历史。

脚本默认 check，apply 要求本机 local、准确数据库名和仓库外备份路径。固定七张属性表清空，不使用 CASCADE；备份同时覆盖分类依赖数据，商品、SKU 及商品属性历史存在时拒绝。备份后锁定并复核，清空、插入、分类版本更新及核验在同一事务中完成，提交后重新连接核验。每次重建生成新 UUID v7。脚本不做增量合并、不修改表结构。

## 风险与回滚

- 同编码异义不得自动合并。源记录必须具有可追溯去向。
- 重置仅允许无商品及历史属性引用的本机开发库；外键新增、环境不符和备份失败均阻断。
- 清空与导入失败回滚；成功后的恢复遵循备份说明，不覆盖后续业务写入。
- 普通描述及价格编辑不得触发规格转换；显式转换提示归档和库存盘点影响。
